# iOS 认证与视觉规范

## 认证流程

应用启动时由 `AuthStore` 检查 Keychain 中的会话：

```text
启动
-> 有本地会话：进入主界面
-> 无本地会话：显示登录页
-> 登录成功：保存 AuthSession 到 Keychain 并进入主界面
-> 注册成功：保存 AuthSession 到 Keychain 并进入主界面
-> 主动退出：先清除本地会话，再尽力通知服务端
```

前端使用以下接口契约：

### 登录

```http
POST /api/auth/login
Content-Type: application/json

{
  "account": "user@example.com",
  "password": "******"
}
```

响应遵循项目统一的 `code/message/data` 包装：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "accessToken": "token",
    "user": {
      "id": "1",
      "email": "user@example.com",
      "displayName": "Trader"
    }
  }
}
```

### 注册

```http
POST /api/auth/register
Content-Type: application/json

{
  "account": "trader",
  "password": "******"
}
```

注册成功后响应与登录一致，会直接返回 `accessToken`。如果账号不是邮箱，服务端
会用 `账号@local.invalid` 填充数据库邮箱字段。生产环境可通过
`APP_REGISTRATION_ENABLED=false` 关闭自助注册。

### 退出

```http
POST /api/auth/logout
Authorization: Bearer <accessToken>
```

Java 服务已使用 Sa-Token `1.45.0` 实现以上接口。Sa-Token 会话保存在 Redis，
密码使用 `PBKDF2WithHmacSHA256` 摘要保存在 `app_user` 表。iOS 在
`Info.plist` 中读取由 `Config/*.xcconfig` 展开的 `API_BASE_URL`，当前提供
`TradeTool Dev A` 和 `TradeTool Dev B` 两个开发地点 scheme；需要在真机上直接
运行生产配置时选择 `TradeTool Release`，归档也使用同一 `Release` 构建配置。
生产发布前核对 `Config/Release.xcconfig`。接口错误继续由请求层统一拦截，并使用
居中轻提示展示。开发环境使用局域网 HTTP IP 时，通过 `Info.plist` 中的
`NSAllowsLocalNetworking` 放行本地网络，不开启全局任意 HTTP 加载；同时声明
`NSLocalNetworkUsageDescription`，用于真机首次访问局域网后端时的系统权限说明。

Keychain 会话按 `API_BASE_URL` 的协议、主机和有效端口隔离。Dev A、Dev B 和
Release 切换时只读取当前 API 来源的令牌，不会把开发环境令牌发送到生产服务器，
也不会因生产环境 `401` 清除开发环境会话。从旧版共享 Keychain 结构首次升级时，
应用会删除来源不明的旧令牌；每个环境首次使用可能需要重新登录一次，之后切换配置
会恢复各自的会话。

设置页与登录页均提供运行时服务器切换。`AppRuntime` 先匿名检查目标服务，再关闭旧
容器的 HTTP / WSS 与页面任务，保存来源并重建根视图。目标来源存在 Keychain
会话时恢复自己的登录态，首次连接则显示登录页；切换失败不保存新来源。每个容器
使用独立认证通知中心，避免旧来源迟到的 401 使新来源退出。应用内完整重新载入
不调用 iOS 退出或私有重启接口。细节见
[服务器切换设计](../../../docs/plans/2026-10-31-server-switching-design.md)。

## 安全约束

- 访问令牌和用户会话使用 iOS Keychain 保存，并按 API 来源使用独立命名空间。
- Keychain 可访问级别为
  `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`，不会随设备备份迁移。
- 密码只用于本次登录请求，不落盘、不写入日志。
- 退出时无论服务端请求是否成功，都会先清除本地登录状态。
- 任意已认证请求返回 `401` 时，统一请求层会清除 Keychain 会话并返回登录页。
- 单独页面不保存或复制访问令牌。

## 设置页与 Binance API

设置页与行情页跟随同一亮色/暗色外观，使用 `#FCD535` 主操作色和红绿盈亏语义：

- 顶部账户卡使用强调黄的 `16%` 透明度背景和 `24%` 透明度边框。“绑定 API、止损额设置、止盈止损策略、下单设置”按此顺序合并为一个四行容器；“暗色模式、策略通知”合并为另一个两行容器。
- 未绑定时，账户资产区域直接显示一行“API 未绑定”，默认 `10pt`、中等字重，并随动态字号缩放，不再显示重复的圆角状态块；止损额和下单设置尚未配置时显示“未设置”。
- 同组行之间使用细分隔线，标题统一为 `body.medium`（默认 `17pt`），辅助说明为 `caption2`（默认 `11pt`）；图标容器 `34pt`，选项行至少 `56pt`，开关行至少 `60pt`，组间距 `16pt`。
- 持仓页未绑定状态的连接图标可点击，push 同一个 API 绑定页面；返回时刷新持仓与账户状态。
- iOS 直接保存 Binance Secret、直接签名请求 `fapi.binance.com` 的原型方向已经
  否决并删除。客户端不再包含 Binance HMAC、Binance 凭证 Keychain 或私有
  Binance URL；升级时会清理旧凭证 Keychain 项。
- 绑定 API Key/Secret 时，iOS 只通过本项目 HTTPS API 一次性提交给 Java 服务。
  Java 验证后加密保存，客户端只能读取 API Key 掩码、账户同步状态、余额与仓位，
  永远不能取回 Secret。
- 建议用户为本系统创建独立 API Key，只开放 USD-M 读取与交易权限、关闭提现，
  并把 Java 服务器固定出口 IP 加入白名单。
- 止盈止损策略支持 1–5 级：每级配置盈利 R、减仓比例、一次移动到固定 R，或持续
  保持“当前浮盈减 N R”。策略列表、编辑和删除都通过 Java API，iOS 本机只允许
  短时缓存展示值，不能成为风控事实来源。
- 止损额页面使用 1%–25% 滑杆并显示低/中/高风险、余额计算式和冻结后的金额。
  iOS 只提交整数比例；Java 负责金额计算以及“调低立即、调高 2 小时后生效”。
- 下单设置页不显示顶部说明卡；保存按钮通过底部安全区固定展示，长页面正文必须
  为固定操作栏预留滚动空间，最后一项可以完整滚动到按钮上方。
- 完整后端边界、状态机和上线顺序见仓库根目录
  `docs/TRADING_BACKEND_DESIGN.md`。Phase 1 只完成按需账户/仓位只读同步、分级
  策略和止损额参数保存，真实执行硬关闭，设置页不能声称已经持续保护真实仓位。

外观状态由 `AppAppearance` 定义，以 `TradeTool.appearance` 存入设备级
`UserDefaults`。未设置时使用亮色；设置页“暗色模式”采用与策略通知一致的开关行，
关闭时使用亮色、开启时使用暗色，重启和
退出登录后保留。根视图统一设置 `preferredColorScheme`，页面与业务弹层继承，
不重建会话和行情订阅。压力测试入口固定暗色，以保留原有基准。

Metal 不读取全局外观状态：`RenderState.appearance` 显式携带主题，编码阶段通过
`ChartColor.resolved(for:)` 处理背景、文字、网格、价格标记与十字光标。静态 GPU
缓冲的复用同时检查场景 revision 和外观；交互帧继承当前主题。切换时共享历史、
视口、几何和字形图集。离屏渲染也使用同一颜色解析。暗色图表、宿主视图、加载空白区及 Metal 清屏统一使用 `#212731`，网格使用 `#333B47`；蜡烛及指标配色保持既有语义。
亮色蜡烛为 `#2EBD85 / #F6465D`，黄色指标线使用更深的同色系以提高白底可读性。

组件规则：

- 默认亮色，设置可切换暗色，突出实时数字信息。
- 信号、设置标题和持仓顶部三个页签统一使用 `modalTitle`（`headline.semibold`）及 `primaryText`。
- 信号卡片的时间独占顶部一行并靠右，行高仅由时间文字的自然高度决定，与主体间距 `4pt`。下方主体独立排列方向图标、左侧交易对与策略信息、右侧价格区域，三者垂直居中对齐；价格数字在上，“价格”标签在下，二次提醒状态保留在左侧策略信息下方。交易对使用公共 `listSymbol`（`subheadline.semibold`，默认 `15pt`）。卡片水平内边距 `12pt`、垂直内边距 `10pt`，列表行上下间距各 `4pt`。
- 根页面、二级页面和业务弹层统一跟随当前主题，灰色用于卡片和输入容器。
- 主操作使用黄色填充，危险操作只使用红色文字或弱红色背景。
- 行情价格使用等宽数字，涨跌方向固定使用绿/红语义。
- 卡片圆角控制在 `10–14pt`，避免过度拟物和大面积渐变。
- 底部导航完全由自定义组件管理，根页面常驻切换，不创建系统 `TabView`。
- 错误反馈使用居中、自动消失的轻提示，不使用阻断式系统 Alert。
- “策略通知”开关控制 APNs 设备注册；首次开启请求通知权限，关闭后通过鉴权接口停用
  当前安装的服务端设备记录。通知点击返回根导航并打开“信号”页，信号卡片点击进入
  对应 K 线详情。
- 系统通知由 Java 直连 APNs 发送，不依赖 App 或 WebSocket 存活；
  `strategy.signal` 只负责在线页面数据更新，不能在客户端重复生成本地通知。
- AppIcon 与启动页使用同一黑底黄白交易品牌标识；启动页只做静态品牌呈现，不执行
  网络请求或模拟加载进度。
- 页面左右主边距为 `16–24pt`，列表采用紧凑交易数据密度。

所有颜色和基础组件集中在 `Core/Design/BinanceTheme.swift`，新页面不得散落
重复十六进制颜色。

## 页面绘制标准

本项目 iOS 页面是手写 SwiftUI 页面。Figma、截图和竞品页面只用于判断结构、
信息层级、交互意图和视觉气质，不能直接照搬截图里的字号、按钮高度、间距和
设备状态栏。最终实现必须回到本 App 已有设计系统，优先对齐 `LoginView`、
`SignalsView`、`SettingsView` 和系统底部 Tab Bar 的尺度。页面可以像
交易 App 一样紧凑、清晰、数值优先，但实现方式必须是本项目自己的 SwiftUI
代码和设计 token。

不得把逆向第三方 App 作为设计依据，包括但不限于解包 IPA、反编译、Hook、
提取私有资源、还原闭源布局代码或复制商标素材。允许使用的参考来源只有用户
提供的截图、公开产品截图、人工观察到的交互行为和本项目已有代码。

如果用户要求“用 Figma 设计能力”但没有明确要求创建或修改 Figma 文件，只做
设计分析和本地 SwiftUI 实现，不在 Figma 中创建节点、组件或页面。

### 公开 Binance Web 取样

2026-07-28 使用 Chrome 检查以下公开页面，移动视口约 `414 × 896`，DPR `2`：

```text
https://www.binance.com/zh-CN/markets/overview
https://www.binance.com/zh-CN/trade/BNB_USDC
```

取样结论：

- 页面 body 声明字体为 `BinanceNova, Arial, sans-serif`。
- `@font-face` 中 `BinanceNova` 覆盖 `200–300`、`400`、`500`、`600`、
  `700–800`、`900` 等字重。
- 行情列表、交易对、价格、涨跌幅和 K 线指标的 computed `font-family` 都是
  `BinanceNova, Arial, sans-serif`，没有观察到数字单独切到第二个字体族。
- 用户感知到的“数字字体不同”，主要来自数字中等字重、紧凑列宽和表格数字对齐。
- `BinanceNova` 是第三方网页字体，不得从网页提取、打包或复制到 App。只有在
  拿到合法授权字体文件后，才能通过 `Info.plist` 和 `Font.custom` 接入。

iOS 当前采用合法映射：

- 普通文本：`BinanceTheme.Typography.text`，映射到 iOS 系统文本字体。
- 数字价格：`BinanceTheme.Typography.number`，映射到 iOS 系统文本字体并启用
  `.monospacedDigit()`，用于价格、成交额、涨跌幅、K 线指标等需要稳定列宽的
  内容。

公开页面中高频可见字号为 `12px`、`14px`、`16px`；交易页主价格使用约 `28px`
中等字重。App 不直接换算 px，而是映射到 SwiftUI 语义字体，保持 Dynamic Type
和系统可访问性。

公开页面取样到的结构尺度：

| 区域 | Binance Web 移动视口取样 | App 转译 |
| --- | --- | --- |
| 市场概览顶部频道 Tab | `16px / 500`，行高 `24px`，Tab 区高约 `62px` | App 不使用频道切换，只显示固定“合约”标题 |
| 市场概览表头 | `12px / 400`，行高 `16px` | `tableHeader` |
| 市场概览行 | 行高约 `64px` | 行内垂直 padding `10pt`，保持紧凑 |

| 市场概览价格 | `16px / 500` | `marketPrice` |

### 参考图转译流程

从截图或 Figma 参考重画页面时，按以下顺序处理：

1. 先拆结构：识别顶部搜索、分组 Tab、工具入口、表头、列表行、底部操作区等
   页面职责。
2. 再删无关元素：去掉系统状态栏、广告、二维码、交易所品牌导航和用户没有要求
   的频道标签。
3. 再映射到本项目 token：颜色使用 `BinanceTheme`，按钮和输入框使用公共
   modifier 或 style。
4. 再定密度：行情页偏紧凑，表单页偏舒展，二级编辑页居中标题和底部操作栏要和
   主 App 尺度一致。
5. 最后看真机效果：优先保证中文、长交易对、小屏和键盘弹出时不漂移、不遮挡、
   不出现残影。

### 字体层级

优先使用 SwiftUI 语义字体，少用硬编码 `.system(size:)`。只有图标、Logo 或
极少数展示性数字确实需要精确控制时，才单独设置字号。

| 场景 | 推荐 token |
| --- | --- |
| 根页面标题 | `BinanceTheme.Typography.rootTitle` |
| 二级页面居中标题 | `BinanceTheme.Typography.modalTitle` |
| 选中 Tab / 分组标题 | `BinanceTheme.Typography.selectedTab` |
| 未选中 Tab | `BinanceTheme.Typography.tab` |
| 表头 | `BinanceTheme.Typography.tableHeader` 或 `sectionHeader` |
| 行情行主标题 / 交易对 | `BinanceTheme.Typography.listSymbol` |
| 行情行副标题 / 说明 | `BinanceTheme.Typography.marketDetail` |
| 价格和成交额数字 | `BinanceTheme.Typography.marketPrice` 或 `marketPriceSecondary` |
| 涨跌幅数字 | `BinanceTheme.Typography.marketChange` |
| 小标签和辅助元信息 | `BinanceTheme.Typography.smallLabel` |

行情和信号列表使用正文级字号；账户卡余额使用 `balance`（`largeTitle.semibold`）
建立主次层级。所有价格与盈亏启用等宽数字，避免更新时位移。

| 行情列表行高 | 最小 `60pt`；设置行最小 `56pt` |
| 编辑列表行操作区 | 约 `52pt` 高 |
| 顶部工具图标 | 图标 `18–22pt`，可触达区域至少 `44pt` |
| 组间 / 项间距 | `24pt / 12pt`；细节使用 `4 / 8 / 16pt` |

所有可点击控件应提供不小于 `44pt` 的可触达区域。列表中的视觉图标可以
更小，但按钮 frame 要保证手指点击舒适。

### 行情页专项标准

行情首页参考交易所 App 的信息密度，但不复制其完整导航结构：

- 第一屏只保留搜索、固定“合约”标题、编辑图标、表头和行情列表。
- 不要加入“自选、加密货币、传统金融、Alpha、预测、金融增长”等频道标签，除非
  用户明确要求。
- 首页搜索框和搜索页输入框的可视高度统一为 `46pt`、圆角 `8pt`，通过透明外层
  将可点击高度扩展到 `48pt`。首页入口不直接接收键盘输入；点击后通过当前
  `NavigationStack` push 行情搜索页，页面从右侧进入并隐藏底部导航。搜索页进入
  后自动获取焦点并拉起键盘，左侧使用与“编辑自选”一致的无底板返回箭头。
- 搜索词为空时显示“热门交易”，严格按后端 24h 成交额降序排列；首次显示 10 条，
  “查看更多”使用黄色 `caption.semibold` 并按页追加。输入搜索词后直接显示合约
  结果，不增加“所有/现货/Alpha”等分类页签，也不显示“现货”标识。
- 搜索请求防抖约 `280ms`；输入币种、完整币对或带 `/` 的币对都应命中，搜索结果
  滚动到底后自动读取下一页。
- 搜索结果行最小高度为 `60pt`。交易对显示为连续的 `BTCUSDC`，基础币种与报价资产
  使用相同的 `subheadline.semibold` 和主文字色，中间不显示 `/`；价格使用
  `footnote` 等宽数字，涨跌幅使用 `caption2`。
- 搜索结果返回后，将当前结果交易对与首页自选交易对合并为同一个
  `market.ticker` WebSocket 订阅；价格和 24h 涨跌幅继续实时更新，离开搜索页后
  清除临时交易对并恢复首页订阅。
- 行情页不提供“持有币种”分组，不显示宫格切换图标。
- 搜索框、“合约”标题、编辑图标和表头固定；只有币种行情行进入垂直滚动区域。
- 表头三列为“名称 / 成交额”“最新价”和上下排列的“24h / 涨跌幅”，时间口径与实时数据保持一致，字体使用
  `.caption2.semibold`，价格列约 `78pt`，涨跌幅列约 `76pt`。
- 名称、成交额、最新价和 24h 涨跌幅均可在本地排序。每个排序入口右侧固定显示
  上下两个实心小三角，当前方向使用主文字色，另一方向降低透明度；不要使用
  `arrow.up.arrow.down` 等单个组合箭头。
- 首次点击名称按升序排列，首次点击成交额、最新价或 24h 涨跌幅按降序排列；
  第二次点击同一项切换方向，第三次点击取消排序并恢复用户自定义列表顺序。
  数值相同时按交易对名称升序，保证 WebSocket 更新期间列表顺序稳定。
- 行情行左侧直接显示交易对和名称成交额，不预留币种图标列；右侧为价格和涨跌
  幅标记。涨跌背景为 `#32BD82 / #F6485E`，文字白色 `caption.semibold`（默认 `12pt`），圆角 `4pt`。
- 行情首页、编辑自选和搜索结果的交易对都显示为连续的 `BTCUSDC`：基础币种和报价资产
  与信号交易对共用 `listSymbol`：`subheadline.semibold`（默认 `15pt`），同为主文字色，中间没有 `/`。主价格为 `13pt` 等宽数字，成交额和次级价格为 `11pt`，永续标记为 `11pt`。
- 行情首页使用主题背景；搜索框使用 `elevated` 背景，文字及图标采用 `footnote`（默认 `13pt`）；编辑
  图标 `18pt`。底部导航同为主题背景，按钮区最小高 `48pt`，图标 `22pt`，文字使用默认 `10pt` 并随动态字号缩放；亮色选中项为 `#010101`、未选中为 `#767676`，暗色选中为金黄 `#F0B90B`、未选中为灰白 `#929AA5`。
- 价格必须使用等宽数字，涨跌幅红绿语义固定，不随主题或截图变化。
- 编辑图标使用 `pencil.line`，保持“斜笔 + 底部短线”的轮廓，点击后进入行情
  列表设置页。

### 行情列表设置页专项标准

编辑页是二级全屏页面，应隐藏底部导航，使用自定义顶部栏：

- 顶部栏高度约 `54pt`，标题“编辑自选”居中，字体 `.headline.bold`。
- 返回按钮使用 `18pt` 的 `chevron.left`，按钮容器约 `40pt × 40pt`。
- 编辑页只管理合约行情列表，不提供“持有币种”分组或对应切换页面。
- 表头四列为“市场”“固顶”“移到顶部”“拖动”，右侧列宽分别约 `44pt`、
  `68pt`、`44pt`。
- 行内复选框为 `20pt`，描边 `1.5pt`；交易对使用 `.subheadline.semibold`，
  “永续”使用 `.caption`。交易对紧跟复选框，不显示币种图标。
- 固顶和移到顶部图标为 `19pt`，拖动图标使用 `19pt` 的
  `line.3.horizontal`，操作按钮高度约 `52pt`。
- 底部操作栏固定在安全区上方，包含“全选”“添加到群组”“移除”，按钮高度约
  `44pt`。
- 当前未实现的操作可以置灰，但不能使用过大的按钮或截图级别的大字号。

### K 线详情页专项标准

K 线详情页是从行情列表 push 进入的二级页面，当前使用原生 SwiftUI 页面结构和
`Metal + Core Text + UIKit` 自研 K 线图：

- 顶部只保留固定的 `53pt` 合约栏，不参与正文滚动。交易对使用 `17pt semibold`，
  永续标签使用 `9pt medium`，副标题直接显示实时价格和 24h 涨跌幅。原顶部页签、
  大块行情摘要和周期工具栏已删除，周期统一通过底部滚轴切换。
  顶部不再显示铃铛，收藏星占用原铃铛的最右侧按钮位置，触控区域为 `44pt`。
  顶栏左内边距 `4pt`、右内边距 `11pt`，返回与币种信息间隔 `6pt`。
- 底部工具、做多和做空操作栏固定在安全区上方，不覆盖正文；主应用底部导航在
  详情页隐藏。操作按钮最小高度 `44pt`，左侧依次为“指标 / 当前杠杆 / 设置”。
  原有入口与布局保持不变，操作栏顶部不画分隔线，按钮上方必须保留 `8pt`
  主题背景间隙，不能直接贴住正文内容。
- 顶部和底部之间只有一个正文垂直 `ScrollView`，仅放置图表和时间轴。
  首屏只显示主图、紧贴主图下方的时间轴和第一个已开启副图；其余副图保留在下方滚动区域，
  不再附加重复指标行、周期收益或盘口。
  副图按开启顺序排列，关闭重开排到最后；切换币种、周期和正常重启后保留顺序。
  底部指标选项栏仍保持原有顺序，不随图中副图顺序移动。
- 主图吸收新增可用高度；每个副图保持 `72pt`，时间轴保持 `24pt`。
  副图底部预留 `16pt` 指标名称与数值区，绘图区位于文字上方；常态与十字光标
  选中态使用同一底部基线。背景为横向长方格：三列网格，横线按绘图区高度适配，单格宽高比至少 1.8；主价格轴刻度仍落在横线上。网格线和十字竖线按绘图区分段，不能穿过时间轴或文字。
  默认价格比例以原 `298pt` 主图（`268pt` 绘图区）为基准，新增空间用于扩大
  可显示价格范围，不自动拉长蜡烛；横向宽度和手动价格轴缩放逻辑保持不变。
  真实 K 线、EMA21/55/144、SuperTrend、VOL、MACD、
  RSI、坐标轴、十字光标和价格标记都由生产 Metal 场景绘制，不得硬编码某个币种
  的数值。
- 默认横向槽宽 `7.6pt`，在 `390pt` 宽页面初始约显示 `43` 根 K 线，支持既有缩放范围。
  EMA 默认参数为 `21 / 55 / 144`，依次使用 `#2DBD85 / #3860F6 / #71269C`。
  颜色来自用户参考图转为 sRGB 后的实色取样；EMA 使用独立 token，不影响 MA、BOLL、MACD 的配色。
- BOLL 使用以窗口价格为基准的两遍方差计算，避免高价低波动时浮点抵消形成异常尖峰。
  指标历史与实时线、画线工具及圆角标记边框共用 Metal 覆盖率抗锯齿与圆形端点，覆盖斜线、折线和虚线；
  直线网格与填充条继续保持原像素对齐方式。
- 首次进入、切换周期、无数据或 Metal 场景尚未完成时，图表槽位必须清空并在正中央
  显示 Binance 风格 4 柱黄色波形加载器；不能显示旧周期画面、静态蜡烛或模拟指标。
  图表横向/缩放/价格轴/十字光标手势继续与父级纵向 `ScrollView` 按既有规则仲裁，
  不得破坏外层页面滚动和固定底部菜单的上下分区契约。横向拖动、惯性、双指缩放
  和价格轴缩放必须在手势进行中连续出帧；场景重建采用单在途、只保留最新请求的
  合并队列，不能因高频状态变化等到手势结束才显示结果。
- 固定底部快捷栏高度 `52pt`，从左到右为指标/副图横向选择区、币种滚轴、周期
  滚轴。指标选择区使用独立横向 `ScrollView`，文字保持 `13pt`，不能带动正文
  横向移动；启用态使用主文字色，其余使用次文字色。币种与周期滚轴的尺寸、
  吸附和中央滚动预览保持不变。指标参数设置由下方操作栏的“指标”入口打开，
  使用原图表设置的 `18pt` 图标。
- 底部周期滚轴支持 `1分 / 5分 / 15分 / 1小时 / 4小时 / 1天`，尺寸与交互不变。
  详情页各周期通过 REST 按需读取币安连续合约 K 线，不写 MySQL、不触发策略或提醒。
- 详情页价格与下单按钮使用 `positive / negative` 语义色，做多、做空及划线提交按钮在亮暗主题下均为白色文字，底栏水平边距 `15pt`。
  图表蜡烛与指标使用独立的 `ChartColor` 主题解析，不修改交易方向或指标含义。
- 详情页同时订阅当前交易对的 `market.ticker`、所选周期 `market.kline`，以及高周期
  页面共用的原生 `1m market.kline` 实时价格源。图表所有周期最多每 `250ms` 发布
  一帧；ticker 更新顶部价格和 24h 涨跌幅，并作为实时价格兜底。所有周期
  每 `15s` 通过 REST 快照校准，`1h` 不做例外。
- K 线页不得引入 SciChart 或其他商业图表包，也不再配置图表许可证；不得复制
  币安私有图片、字体或闭源图表代码，也不得恢复已删除的盘口与成交预览。
- 当前价虚线靠近 K 线的端点必须在拖动和双指缩放期间逐帧跟随，右侧价格轴端点与
  价格标签保持固定，不能等待手势结束后再跳转。

### 布局规则

- 新页面必须复用 `BinanceTheme`、`.binancePanel`、`.binanceInput`、
  `BinancePrimaryButtonStyle` 和 `AppToastCenter` 等公共能力。
- 行情这类交易列表优先使用 `ScrollView + LazyVStack` 实现自定义行，只有需要
  系统行编辑行为时才使用 `List`。
- 列表行采用“左侧信息自适应、右侧价格和操作固定宽度”的结构，避免文本挤压、
  重叠或跳动。
- 交易对、价格、成交额等可使用 `lineLimit` 和 `minimumScaleFactor` 做兜底，
  但不能把全局字号随屏幕宽度缩放。
- 互动图标必须有 `accessibilityLabel`。纯装饰图标使用
  `.accessibilityHidden(true)`。
- 不复制截图里的系统状态栏、广告、二维码、品牌 Logo、底部交易所导航等无关
  元素，除非用户明确要求。
- 币安官方 USD-M `exchangeInfo`、资产和 ticker 接口不提供币种图标地址。行情
  列表不使用字母圆形占位图标，也不依赖币安网页内部的非公开静态资源接口。
- 页面文案保持简洁，Toast 不加句号，尽量少用逗号。
- Toast 默认不显示图标，默认展示 `1500ms`；只有确有必要强调语义时，调用方才
  显式传入图标或自定义展示时长。
- 异常弹框和 Toast 不使用关闭叉号图标；Toast 层级应高于键盘和页面内容，并
  尽量保持屏幕居中，不随输入框区域被顶走。
- 根视图统一监听键盘外的点击和拖动，触碰或滑动任何非文本输入区域时收起键盘；
  监听不能吞掉按钮点击、列表滚动和系统手势，触碰输入框本身时必须保留焦点。

### 导航规则

- `RootView` 只负责登录状态切换；登录后的 `MainAppView` 使用一个根级 `ZStack`
  常驻行情、信号和设置三个顶层页面，不创建系统 `TabView`，从结构上杜绝新版
  iOS 悬浮椭圆 Tab Bar。
- 每个顶层页面拥有独立 `NavigationStack`，通过透明度、点击响应和辅助功能状态
  切换可见页面，三个页面不会因切换被销毁。业务页面不得自行创建底部菜单。
- 全局 `BottomNavigationBar` 只允许在根容器创建一次。`MainAppView` 使用
  `VStack(spacing: 0)` 明确分隔常驻页面 `ZStack` 与底栏，不能把底栏覆盖在页面
  上，也不能挂到某个选中页面上；滚动区域的底边必须止于底栏上方。
- 底栏使用类似微信的贴底通栏结构：纯色背景、顶部细分隔线、图标加短文字，不
  使用悬浮胶囊、圆角容器、阴影、模糊或玻璃材质，背景延伸覆盖底部安全区。
- 底栏按钮区最小为 `48pt`，顶部 `7pt`、底部 `5pt`；图标在按钮区内自然居中后，
  距离顶部 `0.5pt` 分隔线约 `9pt`。分隔线使用 `border` 色，底部安全区只延伸
  当前主题背景。
- Tab 切换通过无动画事务立即完成，移除继承的 SF Symbol 效果，并使用 identity 内容切换。选中状态只改变
  图标、文字和颜色，避免整条底栏参与过渡。
- 不要使用 `switch selectedTab` 整体替换当前页面。这会让页面切换和安全区重算
  同时发生，容易造成底栏闪烁、位移和页面状态丢失。
- 新增业务页面一律使用当前页面所属的 `NavigationStack` push，从屏幕右侧进入，
  并支持系统边缘右滑返回；不要使用 `.sheet` 或 `.fullScreenCover` 让普通页面
  从底部弹出。
- 需要隐藏底部导航的二级页面，将展示状态提升到 `MainAppView`，由根容器隐藏
  `BottomNavigationBar`；页面本身仍通过 `.navigationDestination` 进入。
- `.sheet` 和 `.fullScreenCover` 只保留给确实属于临时模态任务、系统授权流程或
  用户明确要求从底部弹出的界面。
- 自定义顶部栏中，返回按钮容器约 `40pt`，居中标题使用 `.headline` 级别，不要
  做成主页面大标题。所有二级页面复用“编辑自选”的无圆形底板 `chevron.left`，
  不使用系统导航栏自动生成的圆形或玻璃返回按钮。

### 交付前检查

每次新增或重画 iOS 页面，交付前至少做以下核对：

- 和 `LoginView`、`SignalsView`、`SettingsView` 截面对比字号、按钮高度和列表
  密度。
- 检查是否存在散落的十六进制颜色或不必要的 `.system(size:)`。
- 涉及 `.xcodeproj` 或 `Info.plist` 时运行 `plutil -lint`。
- 新增原生框架或 Swift Package 后，分别构建 generic iPhoneOS 和至少一个
  iPhone Simulator 目标。
- 运行 `git diff --check`，确认没有空白字符问题。
