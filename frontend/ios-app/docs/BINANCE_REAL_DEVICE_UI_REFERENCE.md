## 对 TradeTool 的转译结论

- 可直接采用的是信息密度、`16pt` 页面边距、模块间距和底部导航安全区处理。
- 首页的资产、C2C、活动和内容流与本项目行情提醒目标无关，不应照搬。
- 行情类点击目标应由外层容器保证至少 `44pt`，不要照抄部分仅
  `16–32pt` 的视觉 frame。
- Appium frame 是 Accessibility 元素在屏幕坐标系中的运行时矩形，不等于
  SwiftUI 源码里的约束，也不能推导字体文件、圆角或私有素材。
- K 线等 Canvas/Metal 自绘区域后续只能取得整体容器 frame；内部蜡烛、网格和
  指标需要结合无损截图与手势观察，不应伪造为独立 Accessibility 节点。
- 后续采集优先级建议为：行情列表、合约 K 线详情、信号/提醒可对应页面。下单、
  充值、转账等资金操作页不进入自动采集范围。

### 与当前 TradeTool 实现的核对

当前 `DashboardView` 已采用 `16pt` 页面边距、`78pt` 价格列、`76pt`
涨跌幅列和 `58pt` 行高，和真机取样非常接近：

| 项目 | 币安真机 | TradeTool 当前值 | 建议 |
| --- | --- | --- | --- |
| 搜索框可见高度 | `32pt` | `34pt` | 保留 `34pt`，可读性更好 |
| 搜索点击高度 | 外层区域 | `44pt` | 保留 |
| 行高 | `60pt` | `58pt` | 两者均合理，无需为 2pt 强行照抄 |
| 最新价列 | 右边缘 `287pt` | 宽 `78pt` 右对齐 | 保留 |

| 页面左右边距 | `15–16pt` | `16pt` | 一致 |
| 底部导航项 | `74 × 48pt` | `44pt` 高点击项 | 可按本 App 设计系统保留 |

因此，现有行情列表的结构和列宽方向是正确的。最值得继续吸收的是：稳定的
双行信息层级、价格列统一右边缘、固定宽度涨跌幅胶囊，以及让列表内容在底部
导航后方滚动但保留安全区。

### TradeTool 原生图表决策

TradeTool 已弃用 SciChart，生产 K 线采用无第三方图表依赖的原生
`Metal + Core Text + UIKit + SwiftUI` 管线，并保留真实页面的外层结构和 `396pt`
图表高度。原 SwiftUI `Canvas` 静态图已经完整删除。

- 首次进入、周期切换、无数据和场景构建期间只显示图表中央的 4 柱黄色动态加载器；
- 加载器真机测量约为 `21.3pt × 10pt`，单柱约 `3.3pt`、间距约 `2.7pt`，使用
  Binance yellow `#FCD535`；
- 旧周期 `RenderState` 与新周期 `stream + epoch` 不匹配时不能显示，避免切换闪回；
- 标题、行情摘要、周期、指标、阶段涨跌、盘口和固定底栏仍沿用既有详情页契约。
