# 文档维护规则

每次任务完成时评估长期维护信息，更新对应主题的唯一主文档。目录由 [docs/README.md](README.md) 维护；当前流程、代码和配置是事实依据。

- 架构和协议更新 [整合说明](INTEGRATION.md) / [架构](architecture.md)；业务规则更新交易、资金、模式、研究或通知主题。
- 配置、开发和发布方式分别更新 [配置](configuration.md)、[开发](development.md)、[运维](operations.md)；实际验收和上线写入 [变更](changes.md)，标注日期与范围。
- 将当前实现、待实现和待验证分开。历史发布不是本轮验证，测试替身、模拟器和编译不是实盘或真机通过。
- 原 USDT / USDC 的历史材料只在 [来源索引](sources.md) 指定的本地目录和 Git 基线查询；当前项目不再维护参考副本或第二份旧操作手册。
- 临时实施计划在完成后将维护结论合入主题文档并移除；历史恢复使用 Git。
- 凭证、完整环境文件、私钥、真实账户资料和运行输出不加入文档或版本控制。
- 交付前检查链接、源码路径、示例、敏感信息、`git diff --check` 与未追踪文件。安全的新交付文件加入追踪，保留用户其他改动。
