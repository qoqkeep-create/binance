# 全仓审阅问题修复实施计划

**Goal:** 修复已知事项 REVIEW-01 至 REVIEW-13，保持原交易规则和模块边界，减少无界查询与重复请求。

**Architecture:** 复用现有订单身份、平仓适配参数、DRF 响应、调度入口和前端 API client。交易恢复不增加状态机；数据库查询在分页或摘要阶段限制范围；通知投递不进入交易成功路径。

**Tech Stack:** Django / DRF、MySQL / Redis、React / TypeScript / Zustand、现有测试与合成交易所替身。

用户已于本会话明确要求全部修复，按以下分组并行实施；既有工作区审阅文档保留。应用变更、测试与文档完成后，再依据生产边界决定发布，不将本地验证写作线上验收。

## 1. 仓位身份与接管（REVIEW-01、02）

- 修改 `server/trading/external_positions.py`、`server/trading/views.py`、`server/trading/services.py` 及 `server/positions/views.py` 平仓调用。
- 先覆盖已撤销零成交限价单的遗留请求、真正未知开仓请求、成交后已结束 Web 仓，以及旧多仓快照后出现新空仓的回归。
- 扫描只放行已有明确归属和终态证据的请求；不删除请求、不用时间到期证明失败。三个 Web 平仓调用复用 `expected_side`。
- 交叉审查补齐同一证据链：成交数量已知但均价未确认时保持 Web 待确认身份，限价同步、撤单、追单与创建保留数量，后续较旧回包或限频中断不能将其降为零成交。

## 2. 持仓财务、日志与有界加载（REVIEW-03、08、10、11、12）

- 修改 `server/positions/views.py` 及对应回归测试。
- 成交字段存在时允许真实值为零；恢复后重复故障不能被全局去重删除。
- 适配器保留缺失财务字段；完整有限字段才进入金额求和，开仓费缺失继续待补齐。用真实零、非法 Decimal 及账单兜底覆盖同一口径。
- 已关闭历史先数据库分页，与活动减仓投影有界合并；补查仅当前页。维护任务先过滤有效账户资格再限制批次。
- 持仓列表新增 `latest_strategy_error` 字符串，无异常为空；前端取消逐仓全量日志轮询，详情仍按需读取。

## 3. 调度、研究与策略查询（REVIEW-04、05、09、13）

- 修改 `server/trading/scheduler.py`、`server/trading/strategy_views.py`、`server/signal_research/views.py` 及测试。
- 统一后台任务连接清理；研究编辑和发布共用并发边界；样本按真实时间筛选闭合 K 线；删除绕过预取的重复排序。
- 用断连替身、发布与编辑交错、未来 / 未闭合 / 无候选 K 线、查询计数验证最小修正。

## 4. 前端身份、精度与请求生命周期（REVIEW-06、07、12）

- 修改策略编辑页、交易 / 图表价格格式、持仓页及相关测试。
- 编辑 ID 从服务端确认，加载失败或不存在时禁止保存；异步结果遵守当前账户代际。
- 统一小价格有效数字格式；异常摘要消费持仓响应。Profile / Signals 复用已有可见性规则暂停隐藏轮询。
- 验证直达 / 刷新编辑、换账户延迟响应、小价格显示、摘要更新、详情按需请求与隐藏 / 恢复计时器。
