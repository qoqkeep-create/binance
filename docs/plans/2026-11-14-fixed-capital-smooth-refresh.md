# 固定资金规则与连续下拉刷新 Implementation Plan

**Goal:** 止损额度固定为 50–200 USDT；归集仅处理超过 1000 USDT 的部分；持仓／委托页实现自然的下拉提示、松手刷新、完成回弹与稳定滚动。

**Architecture:** 金额规则在后端统一校验，客户端直接提交金额；保留账户模式、绑定代际、Decimal 和资金幂等。刷新使用 SwiftUI `.refreshable` 管理原生刷新控件，移除逐帧 SwiftUI 状态与自绘边距动画；页面只更新所需数据并使用稳定业务行身份。不得向 SwiftUI 滚动宿主手工安装刷新控件，避免被宿主移除。

**Tech Stack:** Django / Decimal、SwiftUI / UIKit、XCTest、隔离 API fixture。

**追加需求：** 成功弹窗图标／交易对居中；明确 Maker post-only 拒绝后有界重报价且未知结果不重复写；对照只读 USDC 来源诊断切网／电梯断网后的恢复，并用本地网络替身验证。用户随后明确要求完成后直接提交、推送和部署完整后端，客户端配套发布与后端部署分别记录。

---

### Task 1: 固定资金规则

- 定位 `server/accounts`、资金归集／预检服务和账户设置客户端；通过余额无关的边界测试复现旧行为。
- 止损 GET／POST 不再根据账户余额换算百分比；50／200 可保存，越界拒绝，不擅自修改已有保护。
- 归集保留上限固定 1000；1000 及以下不归集，只归集超出额；普通／带单保持既有能力边界。
- 同步 iOS／鸿蒙文案与金额输入，验证既有未知结果恢复、绑定隔离和 Decimal。

### Task 2: 刷新复现与修复

- `TradeToolTests/DisplayNumberTests.swift` 使用实际窗口／宿主／UIScrollView 建立旧实现失败的反馈。
- `TradeToolChartCalibrationUITests/ChartCalibrationUITests.swift` 与 DEBUG fixture 给持仓／委托加载可控延迟和计数，验证拖动、释放、加载、完成四个阶段及长列表连续滚动。
- `USDTComponents.swift` 以稳定原生刷新控件管理阈值、指示器与回弹，不替换滚动 delegate，不在每帧拖动时发布 SwiftUI 状态。
- `USDTTradingViews.swift` 收缩刷新数据范围，保留旧卡片直到响应完成，以订单身份识别卡片；页签未选中字号 20→18，间隔增加 6 pt，点击区保持稳定。

### Task 3: 验证与交付

- 金额规则定向回归、相关后端完整回归、原生刷新宿主 XCTest、持仓／委托实际手势 UI、客户端构建。
- 不真实交易、划转或撤保护；客户端结果与部署／TestFlight／手机验收分别记录。
- 更新资金、页面和开发主题文档；检查 `git diff --check`、未追踪文件和独立审查；按已有源码交付授权提交推送。
