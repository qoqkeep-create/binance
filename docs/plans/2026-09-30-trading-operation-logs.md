# 交易操作日志实施计划

**Goal:** 在“我的 → 更多功能 → 日志”展示关键交易动作，尤其系统按规则执行的保护和退出。

**Architecture:** 现有策略日志和已确认成交事件只读汇总；新建轻量操作日志保存缺失的执行过程，不解析服务器日志文件。写日志失败不得改变交易结果，读取接口不查询交易所、不触发交易。按当前用户、模式、API 绑定隔离。

**Tech Stack:** Django / MySQL、现有 React / TypeScript / Tailwind；不增加依赖。

## 1. 日志基础与查询

- 在 `server/positions/models.py` 新增订单关联日志及 `positions.0028` 结构迁移；`server/positions/operation_logs.py` 提供唯一写入入口与分页汇总。
- 写入使用独立保存点保护，记录动作、来源、明确状态、脱敏业务说明及时间；稳定业务身份防重，同一异常持续发生不刷屏。成功只表示动作已确认，未知结果必须显示待确认。
- 在 `server/accounts/operation_log_views.py` / `urls.py` 增加只读 `GET /v1/account/operation-logs`，默认 20、上限 50 条，游标分页，不加载全表。
- 复用策略日志和仓位通知的交易事件，通知是否投递成功不参与交易结果判断；不伪造历史过程日志。
- 测试权限、用户 / 模式 / Key 隔离、同时间分页、去重、敏感信息处理、日志故障不破坏外层事务。

## 2. 关键动作记录

- `server/trading/external_positions.py`：手动仓接管、缺失止损设置 / 恢复、止损收紧、保护异常、超额亏损 / 触价平仓发起和确认、结果未知、残单清理及恢复。
- `server/trading/services.py` 与 `server/positions/views.py`：补齐无策略仓位的自动止损保护及用户保本 / 止盈 / 平仓过程；已有策略行为与确认成交通过汇总呈现，不复制交易状态机。
- 用模拟交易所的回归验证先后语义、持续异常抑制、恢复后再次发生、写日志失败以及原交易路径未改变。

## 3. 页面

- 新增 `tools/src/pages/operation-logs/`，注册懒加载路由，`profile/index.tsx` 的更多功能增加“日志”；带单也能进入，其他原有限制保留。
- 时间倒序显示来源、状态、交易对 / 方向、仓位编号、手动仓标记与完整说明；支持刷新、继续加载、空态与失败后保留已有记录。
- 可见在线首屏每 30 秒查询本地记录，后台 / 离线停止；换用户、模式、绑定时清理并拒绝旧请求覆盖。
- 测试分页与异步隔离、失败保留、计时器生命周期；运行 TypeScript、页面 ESLint、构建并检查页面渲染。
