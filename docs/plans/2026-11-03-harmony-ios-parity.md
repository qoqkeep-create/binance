# iOS → HarmonyOS 原生复刻实施计划

**目标：** 以当前整合版 iOS 前端为唯一视觉和交互基准，在 `frontend/harmony-app/` 分批完成 ArkUI 客户端。尽量保持逻辑尺寸、颜色、图标、文字、页面层次、操作顺序和状态恢复一致。

**架构：** 继续同仓库独立原生工程，共用已有后端协议与鸿蒙安全存储／会话／命令层；视觉组件与业务流程分别对齐。SwiftUI / Metal 无法直接用于鸿蒙，ArkUI / Canvas 实现相同输出与手势，系统状态栏、键盘和窗口使用鸿蒙能力适配。

**技术：** ArkTS / ArkUI Stage、Network Kit、Asset Store、Canvas；本机 API 26 SDK，Mate 80 真机。按用户要求直接分批实施，保留本地修改；不提交／推送、不发布平台、不执行真实交易或资金操作。

## 基准与取舍

- 基准为2026-11-03工作区的实际 iOS 源码，包含用户尚未提交的界面调整；不是来源 USDC／USDT 旧工程，也不是旧截图。记录当前 Git 基线只用于定位，不丢弃工作区改动。
- 原生重建为采用方案：保留已有鸿蒙 core 和后端边界，按页面复刻。WebView 包装无法直接复用 SwiftUI，并增加安全存储、手势与图表差异；重建后端与本次目标无关。
- iOS pt 对应鸿蒙 vp，文字先按默认字号换算为 fp；不同屏幕宽度保持边距／固定控件尺寸，弹层和图表用可用空间比例。中文系统字体、系统键盘、状态图标存在平台差异；不通过拉伸截图或隐藏系统栏制造一致。
- 每批分别记录“代码已对齐”“替身已验证”“Mate 80 已验证”；全量完成前不声称已完全复刻。

## 执行步骤

每批按以下顺序进行，不改 iOS 基准源码：

1. 读对应 iOS 视图、依赖模型、主题和当前鸿蒙页面；记录具体差异与必需协议。
2. 对已报告回归先建立可复现信号。黑边使用真实截图采样，业务行为使用隔离 transport／vault／clock；禁止以源码字符串断言代替实际行为验证。
3. 先实现共享组件与状态，再接页面；金额／幂等／身份继续由现有 core 管理。输入、网络错误、取消、退出和旧响应需同步对齐。
4. 执行 `npm test`、`npm run check`，按改动选择核心 strict 检查和真实 ArkTS 构建；同步源代码到忽略工程，保留其本地签名。
5. 在明确指定的 Mate 80 上更新安装；仅在本应用内验证，截图写忽略目录。需要真实账号才能验证的部分单列待验，不借用生产凭证。
6. 更新本计划的批次状态和 [鸿蒙主文档](../harmony-client.md) 的当前实现；实际验收写 [变更记录](../changes.md)。检查链接、敏感信息、未追踪文件及 `git diff --check`。
