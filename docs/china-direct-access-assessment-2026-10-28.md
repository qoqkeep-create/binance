# 中国大陆直连访问评估（2026-10-28）

## 结论

当前不建议将整站从阿里云 CDN 切到新加坡源站直连。成都移动样本中，浏览器无缓存打开登录页的表单出现时间为 20.84、21.87、27.74 秒；使用 CDN 时两次成功样本为 3.47、4.02 秒，另一次发生导航超时。静态资源缓存命中后的优势明确，但当前 CDN 首页和回源链路也存在波动，仍需单独排查。

有缓存且复用连接时，直连立即重开登录页为 0.37–1.21 秒，CDN 两次有效热打开为 1.44、2.00 秒。这支持继续比较动态请求的直连路径，不能据此推导首次打开、重启 PWA 或所有账户 API 都会更快。

这是单一线路、工作日上午的时点观察。尚未覆盖全国三网、晚高峰、手机实机、真实登录和账户业务，不给出全国速度或可用率承诺。本轮仅作公开接口和页面的只读评估，没有修改 DNS、CDN、服务器配置或执行交易操作，没有提交、推送或部署。

## 行情与账户路径的影响

1. 历史 K 线首屏会失去 CDN 的公共快照分发，首次打开或首次切换到未缓存币种 / 周期更容易受跨境传输影响；已有浏览器行情缓存可以改善首帧，但不能证明数据是最新的。两侧本轮均返回 gzip，公开快照为 `max-age=5, s-maxage=1800`。
2. 实时 WS 当前已经直连新加坡，去掉主站 CDN 不会自动改变这条路径。3 次 `BTCUSDT / 1m` 只读连接均收到 3 条有效 K 线：握手分别 2.994、2.584、5.649 秒，首条有效消息分别 3.597、2.584、6.916 秒。观察窗口很短，未验证晚高峰长期断线率、其他币种或 REST 故障兜底。
3. 账户 API 当前通过主站链路回源；`no-store` 表示不缓存，不能理解成网络上绕过 CDN。本轮深度健康经 CDN 的中位数更快，但热浏览器的直连 HTML 更快，二者不足以推导全部动态请求的方向。没有测真实账户查询和交易请求。
4. 普通导航每次联网取得 HTML。浏览器缓存仍能保留哈希静态文件，因此停 CDN 不等于失去所有缓存；发布产生新哈希、换设备、清缓存、浏览器回收缓存时，仍可能回到慢的冷启动。
5. 停 CDN 会将静态流量和 HTTPS 连接负担移回源站，具体容量取决于实际购买带宽、出口质量与并发。本轮未读取云账单、源站配额或做并发压测，无法报出准确节省金额或可承载人数。源站 IP 已由行情域名公开；不能把“首次暴露源站 IP”当作本次新增影响。CDN 上实际启用的防护和访问限制仍需先核对，避免切换时遗漏。

| B：前端静态源站就近托管，经现有 CDN 按路径回源（优先建议） | 将公开 HTML、哈希 JS / CSS、图标、manifest、worker 等前端构建产物部署到实测更近的静态源站，例如合适地域的 OSS；HTML 继续每次联网获取，动态路径仍回现有生产服务 | 入口不再必须经 CDN 回新加坡取静态 HTML；缓存 MISS 也由更近的前端源站处理，同时保留每次获取新入口的行为 | 增加静态托管费用和独立发布步骤；目标地域尚未测速，云配置、备案 / 加速区域条件尚未核对，不能先承诺某地域速度。此方案加速表单出现，不直接证明登录 API、账户数据或 WS 也更快 |

**优先建议 B 的理由**：此前已处理 PWA 旧入口滞留，当前用户同时要求速度和可靠性。B 改善入口取文件的路径，不必依赖延长 HTML 可用缓存期来换速度；A 可作改动较小的备选，但只改善命中，不能覆盖低流量冷节点。两者均未实施。

拟议的 B 路径如下，箭头表示请求路由，非已经上线：

```text
浏览器 → 现有主站 CDN → HTML / 前端静态文件 → 待选的就近静态源站
                    → /api、/v1、/admin、/static、/market-data、/webhook 等服务路径
                      → 现有 47.236.86.243
实时行情 → 现有 stream.ba.wow211.com
```

落地前需核查当前 CDN 条件源站 / 高级回源是否冲突、规则引用额度、OSS 回源 Host / 鉴权、安全响应头及 SPA 深链接回退；不能将所有未知路径无条件回退成 `index.html`，否则会掩盖 API / 资源 404。主站域名保持同源，避免仅为前端部署引入新的跨域登录与 Cookie 依赖。候选地域优先按现有备案和加速区域条件选择中国内地，否则先实测境外候选，不假定香港必然更快。费用应按当前访问量、存储、请求和回源流量核算，本轮未读取账单或给出未经验证的月费。

发布设计需先上传完整哈希资源并验证，再切换 HTML；保留旧哈希资源及与旧页面兼容的 API，避免已打开的页面随后加载 chunk 404。回滚恢复旧入口与旧回源配置；前端发布不应为了更新静态文件重启交易后台。HTML 与 worker 的新旧版本升级、普通刷新 / 深链接 / PWA 恢复、静态 404、安全头及匿名 API no-store 必须分别验收。静态托管方案本身不包含账户 API 共享缓存或交易后端迁移。

### 拟议验收与暂不优先的措施

拍板后先用独立验证域名或隔离测试入口，在同一线路、同一设备与相近时段，对浏览器首次 / 再次打开分别至少 30 个样本作对照，保留失败和超时；同时看 HTML 首字节、表单可见时间、CDN HIT / MISS 和目标静态源站的回源耗时。建议先以本线路两类导航的表单可见 p75 ≤1.5 秒、HTML 首字节 p75 ≤0.5 秒作为候选目标；这是提案目标，尚无候选源站实测，不能写成预计必达或全国 SLA。全国体验需另按三网 / 晚高峰和手机实机验收。若隔离对照未改善或版本升级 / 回滚检查失败，则不切主站。

压缩和 HTTP/2 已有效，前端渲染在原首次样本中约占 HTML 收完后的 0.218 秒，因此继续优先压 JS 体积、换证或仅启用导航预加载，均缺乏消除本次 2–3 秒入口等待的证据。导航预加载只并行 worker 启动和网络获取，不缩短远端回源本身；worker 当前毫秒级启动，不列为首要措施。动态加速 ESA / GA 只在后续明确需要改善 API 链路、并完成同路由对照和成本核算后再评估，不能用购买产品代替本次定位。
