# 项目协作规则

> 来源归档（2026-10-31）：链接已按归档位置调整；当前整合实现与部署见 [整合说明](../INTEGRATION.md)。


本文件适用于整个仓库。先读 [文档目录](../README.md)，根据任务查阅对应业务文档，不以历史计划替代现行实现。

## 工作方式

- 先读代码、相关文档和工作区差异，再修改；保留用户未提交改动，避免无关重构、依赖和锁文件变动。
- 保持现有模块边界。通知和第三方转发通过独立事件、适配器和投递记录扩展，不把网络发送强绑定到交易成功路径。
- 资金金额使用 Decimal / 项目已有精度工具；交易身份、幂等键、状态机和结算口径遵守 [交易安全](../trading-safety.md) 与 [资金文档](../capital-and-transfers.md)。
- 测试按影响范围选择；修复回归先补可复现测试。不得用真实开平仓、划转或撤销保护单作为普通测试。
- 不在仓库、文档、浏览器存储或输出日志中暴露生产凭证。示例使用占位符；不得打印完整生产环境文件。

## 生产边界

- 唯一生产目标为 `47.236.86.243`，部署结构及操作以 [运维文档](../operations.md) 为准；不恢复 OpenClaw 或其他无关业务栈。
- 用户当前允许开发完成且不影响既有持仓时直接通过 webhook 或 SSH 部署。旧“先确认无持仓且 SSH 窗口不超过一小时”限制已暂停；未来 webhook-only 要等用户明确通知，不能提前当作现行禁令。
- 上述授权不包含开平仓、资金划转、撤保护单、改人工接管标记或修改既有订单策略。无法确认改动不会影响既有持仓时，说明风险并取得方向后再部署。
- 不把生产交易操作藏进迁移、启动、健康检查或修复脚本。数据迁移与回滚必须评估新旧代码兼容；代码回滚不会还原数据库。
- 推送 `main` 会触发自动部署，包括纯文档提交。纯文档任务不为“完成部署”而无意义重建生产；交付说明是否已提交、推送、部署。

## 每次任务结束必须评估文档

这不是只在用户要求写文档时执行的步骤。

1. 判断本轮是否改变架构、接口、配置、业务规则、运维方式、安全边界、排障结论或已知问题状态。
2. 有长期维护价值时，主动更新对应主题的唯一主文档；新增主题同时更新目录。不要只把结论留在聊天中。
3. 变更跨主题时更新关联链接；完成待办要标记结果、验证日期和范围。线上部署与验收写入 [变更记录](../changes.md)，不要把本地测试写成线上通过。
4. 将“当前实现”“用户要求但未实现”“待验证”分开。配置和接口以代码核对，云端状态写明最后验证时间；不要仅依据代码注释声称功能存在。
5. 合并过期文档时保留迁移索引或 Git 基线，不删除用户原始材料，不保留多份相互冲突的操作手册。
6. 检查链接、示例、敏感信息及 `git diff --check`。最终答复简要说明更新了哪些文档；没有持久性变化时说明本次无需更新即可，不为凑记录重复抄写规范。

详细归档与维护规则见 [文档维护规范](../maintenance.md)。
