## 访问和部署授权

用户要求通过 SSH 手动发布；自动发布入口已停用，不能根据旧 webhook / timer 说明恢复它们。本轮最新要求为先审阅全部未提交内容，等待用户决定发布范围。旧“先确认完全无持仓、开启最长一小时 SSH 窗口”规定不作为当前限制；不影响既有持仓仍是部署判断边界。

发布权限始终与交易操作权限分开：不允许借部署、数据迁移、启动修复或 SSH 调试撤销保护单、改仓位、转资金或写人工接管标记。不确定兼容性时先说明风险、暂停该生产变更。真实交易动作需要单独明确授权，不由“直接部署”推导。

2026-09-30 用户在明确要求手动仓强制保护、取消后补回和浮亏超额平仓后，进一步明确要求全部推送并部署；本次据此启用这些已指定的后台业务规则。首次上线会接管已有外部仓位的影响已明确告知；没有为测试额外创建或关闭仓位、划转资金。

本项目不恢复 OpenClaw、旧网站或另一套服务。其他服务器不在当前生产范围内。不要公开 SSH 私钥、服务器密码、完整环境文件或 webhook 凭证。

## 发布流程与回滚

1. 本地检查工作区，只纳入当前任务，完成相应测试和文档评估；审查迁移与启动代码的副作用及新旧版本兼容性。
2. 用户决定发布范围后，将审查通过的最终版本提交到仓库并确认完整提交 SHA。推送 `main` 本身不发布，纯文档更新无需为此重建应用。
3. SSH 连接唯一生产目标，使用服务器固定手动执行器发布指定提交。该执行器不随应用发布自动替换；需保留单实例锁、健康检查及失败处理。具体参数以已审查的手动发布基线和固定脚本为准，不能运行本旧分支的自动拉取脚本代替。
4. 检查容器状态、首页、深度健康、运行版本和本次业务的最小验收，不以构建完成作为上线成功。前端还须核对 OSS / CDN 入口及懒加载资源与已确认容器一致，不能仅核对源站 HTML。
5. 保留 last-good 与失败状态记录；失败回滚需同时评估数据库兼容和 OSS 前端版本。不得为重试而启用旧 timer、抹去状态文件或覆盖固定手动执行器。

自动回滚恢复代码，不回退数据库迁移和外部副作用。涉及删除字段、数据转换等变更必须先准备可验证备份与兼容方案。不要用重跑失败版本、手动抹去状态文件、删除数据卷代替排查。生产仓库由部署脚本同步，不直接在其工作区保存唯一修复稿。

带单首次上线分两步：先以 `LEAD_TRADING_ENABLED=false` 发布完整模式兼容代码、迁移并建立新的 last-good；验收后再开放入口。兼容基线 `e966f4b` 已于 2026-09-11 17:46 北京时间上线并通过健康及只读验收。模式字段保留数据库默认值以兼容迁移窗口的旧进程。出现带单绑定或订单后，禁止回到 `3f399f3` 及此前不识别模式的代码；需要暂停时关闭开关，仍保留查仓、平仓、保护和后台任务。不能用反向迁移删除带单数据作为回滚，详见 [带单模式](../lead-trading.md)。

生产于 2026-09-10 只读核验确认：数据库密文由一个独立但仅 11 字符的上一代 AES 密钥写入，并非由 `SECRET_KEY` 写入。轮换必须先发布支持 `AES_PREVIOUS_SECRET_KEY` 的兼容基线，再把原 AES 值原子移入该变量并生成新的 `AES_SECRET_KEY`；重启后全量重写 API 绑定和研究模型密文，验证临时移除上一代密钥时全部记录仍可解密，最后删除上一代密钥并启用严格检查。新写入始终只用当前 AES；不能先换环境变量，也不能在迁移窗口回滚到不认识密钥环的版本。

轮换使用 `python manage.py rotate_encrypted_credentials --dry-run` 统计待重写字段，确认后去掉 `--dry-run` 执行事务迁移，再临时移除上一代密钥并运行 `--verify-only`。命令覆盖 `ApiBinding` 的三个凭证字段和 `ResearchAiModel.api_key_encrypted`；任一字段失败即整批回滚，输出仅含记录和字段数量。

SSH 用于已授权范围的配置或排障时，优先使用版本化模板与原子更新，保留配置备份，先语法检查再平滑 reload；不顺手重启交易后台或批量清理数据。

手动仓保护于 2026-09-30 发布，兼容基线和当前 last-good 均为 `85d47b0`。0027 仅增加兼容字段与放宽未知开仓号，旧 ORM 写入兼容已验证；首次 scheduler 启用会接管外部现有仓位并可能立即平掉超额仓，不能作为普通健康检查运行。出现外部记录后不能回滚到不识别 `position_origin` 的版本，不得将 last-good 手工降回 `0d3bf51` 或更旧版本。保留交易所保护，使用识别新来源的兼容代码回退，禁止删记录或反向迁移绕过。规则见 [交易安全](../trading-safety.md#外部手动仓位强制保护)。

## 只读排障顺序

先确定用户看到的错误发生在 DNS / TLS、CDN、宿主网关、容器网关、API、数据库还是 scheduler，避免直接重建全部服务。

公网检查可在开发机执行：

```bash
curl --fail --silent --show-error --max-time 15 https://ba.wow211.com/v1/health
dig +short stream.ba.wow211.com A
```

下面命令仅在已连接 Trade 服务器、目录为 `/opt/riskon/tradetools` 时使用；日志按任务范围读取并脱敏：

```bash
docker compose --env-file .env.docker ps
docker compose --env-file .env.docker logs --tail=100 backend scheduler
systemctl status tradetools-auto-deploy.timer --no-pager
nginx -t
```

`/v1/health` 检查 DB `SELECT 1`、无待执行迁移、Redis 中新鲜 scheduler 心跳。API 活着而 scheduler 失联不能算健康。私有 API 必须 no-store，不能让 CDN 缓存健康检查或账户响应。

心跳由独立 Redis 任务写入，不能证明每个业务线程的数据库连接或交易任务成功。业务任务入口 / 退出会清理旧 Django 连接；仍须检查对应业务任务错误与恢复日志，不能以健康为绿色替代保护或结算验收。

定位到源站后，可按实际端口绕过 CDN 对比首页与健康耗时；TLS 验证优先保留正确 SNI / 主机名，不把关闭证书验证作为公网验收结果。WS 需看到真实 `kline` 事件，而非只有 `101 Switching Protocols`。

## 前端仍显示旧版本

先核对运行版本、源站与公网首页的资源哈希，以及 `/sw.js` 的内容和 no-store 响应头。后端版本号来自在线接口，不能独立证明浏览器正在运行同版 JavaScript；PWA 导航可能仍由旧预缓存提供 HTML。

2026-09-11 将页面更新策略改为 [独立 worker](../../tools/src/sw.js)：普通导航每次以 `cache: no-store` 获取服务器 HTML，不再缓存或回退到旧页面入口。安装不下载整套预缓存，只需更新小型 `sw.js`；避免某个非首屏资源下载失败使旧 worker 长期保留。带内容哈希的 JS / CSS 仍使用 HTTP / CDN 缓存，兼容读取历史 CacheStorage 中同 URL 的不可变资源；不主动删除旧缓存，不缓存账户 API 或写请求。完全离线时不再提供旧版应用壳，交易本身仍必须联网。

首次从历史 worker 迁移时，浏览器可能先显示已缓存的旧文档；在线启动会检查并接替旧 worker，接替后的下一次普通打开 / 刷新即可获取新 HTML，无须特殊链接。已打开文档或系统恢复的标签页不等于一次新导航，不能承诺其 DOM 自动改变。新客户端不因 worker 激活强制刷新正在操作的页面；历史客户端原有的激活自动刷新仅在迁移阶段仍可能执行。后续即使 `sw.js` 字节没有变化，正常导航也能取得新 HTML。

异常设备仍可使用 [更新网页界面](https://ba.wow211.com/api/frontend-refresh) 作为排障兜底，而非日常更新步骤。这是 Nginx 精确路径提供的静态恢复页，不是 Django 业务 API；`/api/` 已在旧 Service Worker 导航排除列表中，因此能直达网络。页面只注销本站根作用域的 `/sw.js` 注册，随后重新进入 `/profile`；不删除 Cookie、localStorage、sessionStorage 或 CacheStorage，不发起解绑、交易或资金请求。

恢复页与脚本禁止 HTTP 缓存，worker 不缓存它们。恢复失败显示重试按钮，不能重定向假装成功。长期离线或具体 Safari 设备的存储故障仍需在设备侧验证；不要通过清除全部网站数据或修改业务缓存来替代排障。升级回归必须保留真实旧 worker 与缓存，流程见 [开发验证](../development.md#浏览器跨版本升级回归)。
