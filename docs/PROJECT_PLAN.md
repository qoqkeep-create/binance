## 2. 状态与维护方式

任务状态使用 `待处理 / 进行中 / 受阻 / 待验收 / 已完成`。实现提交后先进入待验收；只有满足表中的验收条件并在[开发日志](DEVELOPMENT_LOG.md)记录证据，才标记已完成。所有未指定负责人均为待分配，不推测他人已承诺的工作。

每轮变更维护三处信息：本表更新状态；开发日志追加日期、提交/文件、验证和下一步；受影响的专项设计更新实际行为。问题编号保持稳定，已解决问题保留闭环记录。

文档完善、静态审阅、单元测试、Testnet 联调和生产资金安全是不同的验证范围。每轮只声明有证据支持的结果。

建议将 `SEC-001` 至 `SEC-004`、`VAL-001`、`VAL-002` 的闭环作为实际交易发布评审的核心材料；iOS 图表发布另按[图表架构与实施方案](../frontend/ios-app/docs/KLINE_CHART_ARCHITECTURE.md)的具体阶段门槛验收。排期、负责人和发布窗口待项目维护者确定。
