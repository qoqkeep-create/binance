## 展示与范围

按时间倒序展示北京时间、交易对、方向、仓位编号、手动仓标记、操作来源、结果和业务说明。支持刷新、游标加载更多；页面可见且联网时，首屏每 30 秒刷新。加载历史页后暂停自动刷新，手动刷新回到最新记录。请求失败保留已加载内容；换用户、绑定或模式后清空并忽略旧请求。

日志是已经发生的业务记录，不是服务器原始日志。来源分为系统、手动、策略、成交；策略历史包含人工配置行为，所以不一概标为系统。状态分为已执行、待确认、失败、记录，须结合说明中的具体动作理解：挂单受理不等于保护已核对，保护生效不等于止损已经成交。平仓成功仅来自已确认的仓位终态；通知发送失败不会变成交易失败。无法确认平仓触发来源时明确注明待核实。

| 来源 | 当前覆盖 |
| --- | --- |
| 已有策略日志 | 策略绑定 / 取消、层级达到、保本 / 移动止损、预挂止盈、策略执行失败等已有持久记录 |
| 已有仓位成交事件 | 已确认开仓、减仓、止损 / 止盈 / 手动平仓；与通知投递状态无关 |
| 手动仓保护过程 | 发现接管、设置 / 收紧 / 恢复止损、保护异常及恢复、旧保护与残单清理结果、超额浮亏 / 触价 / 用户发起平仓及待确认 / 拒绝 |
| Web 仓位保护过程 | 无策略仓位也记录止损受理、保护核对、补挂失败与重试、触价紧急平仓及未确认结果 |
| 用户持仓操作 | 立即平仓发起 / 拒绝 / 待确认，保本操作、手动止盈设置与取消结果 |

上线前已有的策略及成交记录可以查看；此前未持久化的过程无法还原，不补造“系统当时执行过”的记录。未成交委托的完整生命周期、未产生仓位的开仓失败、原始技术事件和资金归集阶段不在本页首期范围；资金记录仍见 [转账历史](capital-and-transfers.md#转账历史打开读库刷新才同步)。当前不新增日志自动过期或删除任务。

## 后端与身份

- `GET /v1/account/operation-logs` 为认证只读接口，通过既有 `X-Trading-Mode` 选择模式；参数 `limit` 默认 20、上限 50，`cursor` 为服务端生成的签名游标。返回 `records`、`next_cursor`、`has_more`。
- [operation_logs.py](../server/positions/operation_logs.py) 汇总 `TradeOperationLog`、`OrderStrategyLog`、`TradeNotificationEvent`。各来源最多读取 `limit + 1` 条，按时间、来源与行号稳定合并，不读全表再分页。
- 记录严格限定为当前用户、当前模式、当前 API 指纹所属订单；未绑定或无有效指纹返回空。游标绑定相同身份，不能跨账户 / 模式续页。历史无指纹的订单不猜测归属；相同 Key 重绑可复用原记录，换 Key 后进入另一个范围。
- 查询不构造交易所客户端、不解密凭证、不对账订单、不触发通知或资金动作；前端不将日志保存在 localStorage。
- 不返回 Key 指纹、请求身份、原始交易所响应或通知投递错误。业务说明在写入和读取时都经过凭证、网址、邮箱、地址等信息脱敏，兼顾已有历史文本。

## 写入和故障边界

`TradeOperationLog` 只增加一张关联订单的表（`positions.0028`），包含动作、来源、状态、说明、时间及可选幂等键，不增加新的交易状态机。`record_operation` 是唯一新增写入入口：在保存点内写入，数据库错误被隔离，不把交易成功改成失败，不让保护或平仓因日志失败停止。外层交易事务回滚时其中的日志也回滚；故障期间丢失的过程日志无法保证补回，这不是完整审计账本。

相同订单 / 动作 / 来源的连续相同状态和说明默认合并；确定业务身份的记录使用哈希后的唯一事件键。手动仓恢复以每张实际保护单身份区分，同价连续取消再补挂仍留下各次记录。健康巡检不会每轮重复生成相同日志；业务状态变化会记录，连续相同请求或结果可合并，不保证逐次请求明细。

订单策略详情同样只合并连续重复日志，保留“失败 → 恢复 → 同样失败”的全部状态转换。持仓列表的最新异常摘要与详情共用可见日志过滤规则，并严格限定当前订单策略快照；本页操作日志的三来源游标分页不经过策略详情去重。

迁移仅创建日志表，不读取交易所、不回填业务记录、不修改持仓；旧代码可以忽略该表。但本次发布同时含 [手动仓强制保护](trading-safety.md#外部手动仓位强制保护)，整体发布仍须遵守其既有持仓与回退边界，不能以日志功能的只读页面绕过。

## 验证入口

- `accounts.test_operation_logs`：身份、权限、只读、三来源分页、状态语义、脱敏、日志保存点故障隔离。
- `trading.test_external_operation_logs`：手动仓接管、确认后记成功、连续取消后恢复、未知 / 拒绝、异常恢复、残单清理、写入故障。
- `trading.test_web_operation_logs`：无策略保护、受理与确认、紧急平仓、手动操作、日志失败不回滚业务状态。
- 前端 `operation-logs` 与 profile 入口测试：模式入口、异步隔离、分页、失败保留、计时器生命周期；隔离 MySQL 另验证新表与幂等约束。
