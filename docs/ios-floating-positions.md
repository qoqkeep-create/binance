# iOS 持仓浮窗与 live 卡片

## 使用与范围

2026-11-04 按用户要求移除 App 内浮窗卡片。持仓页右上角“持仓浮窗”纯图标入口保留 44 × 44 pt 点击区，点击直接请求外部系统画中画；不再先显示内部卡片或等 Home 后自动转出。系统负责外部窗口拖动、缩放、播放／暂停、关闭和返回 App，卡片内不提供交易按钮。系统关闭／返回 App、解绑、账户／模式范围改变会收敛开关为关闭，下一次由用户主动开启，不自动恢复旧窗口。

外部画中画使用深色、按当前页行数自适应高度的视频帧：宽度 640 px，1／2／3 行分别为 240／322／404 px；没有持仓或同步中使用 240 px 紧凑占位。每页同时显示最多 3 笔持仓的币种、方向、市价与浮盈，超过 3 笔每 5 秒整组轮播，最后不足 3 笔的一页也按实际行数收缩，保留页码及总笔数。浮盈最多 2 位且去尾零，市价继续原有小币精度；每行分别判断行情有效性，过期行显示 `--`，不因其他币种更新而续期。每份视频帧同时生成对应尺寸的格式描述，源图层与画面保持相同比例，不为行数变化重建 PiP 控制器或强制清空视频层。实际最小尺寸、位置、用户缩放和控制按钮由 iOS 决定，不能强制系统窗口使用像素帧尺寸；系统实际收缩动画及最终外窗比例仍待真机验收。

`FloatingPositionsView.swift` 仍由 `MainAppView` 的 NavigationStack 外层挂载，但仅保留 AVKit 必需的非零尺寸源图层：宽 160 pt、高按视频帧的 1/4 等比更新（1／2／3 行分别为 60／80.5／101 pt），留在真实 window 中，前方同色不透明背景遮住，不可点击且不暴露为内部卡片。未设 hidden／零 alpha／零尺寸，不再使用 inline 自动启动机制。`FloatingPositionsPiP.swift` 独立管理显式启动、最新帧背压和系统回调；启动源尚未就绪时等待，重复点击不重复 start，取消后的旧回调不能重新打开，快速重试等系统上一窗口关闭后继续。

设备不支持、未绑定、音频会话失败或启动超时通过公共 toast 提示并恢复开关关闭，可再次尝试，不回退 App 内卡片。使用公开的 [sample-buffer PiP 接口](https://developer.apple.com/documentation/avkit/avpictureinpicturecontroller/contentsource-swift.class/init%28samplebufferdisplaylayer%3Aplaybackdelegate%3A%29)与既有 `UIBackgroundModes = [audio]`；开启时激活可混音音频会话，停用释放，不播放静音音轨，不申请麦克风、摄像头或通话权限。遮挡源图层的系统可用性、实际启动与跨 App 长时更新仍待新签名包 iPhone 验收，host 和无签名编译不能替代。

## 数据和生命周期

- `USDTStore` 持有共用的只读 `FloatingPositionsModel` 仓位快照与 `PositionLiveQuotes`，持仓卡片及画中画读取同一批数量／均价与同一份 ticker。画中画正在启动／有效播放时，每次 `GET /v1/position/list` 完成后等待 3 秒校对仓位事实；账户事件可提前刷新。持仓页也复用该快照，所有消费者 join 模型持有的独立读取 Task，同账户最多一个请求在途；关闭浮窗或离开某页面不会取消其他消费者仍需要的读取。
- 持仓页与画中画的市价／浮盈通过实际 `PositionLiveValuation` 统一：多仓 `(ticker 最新成交价 − 开仓均价) × 剩余数量`，空仓反向；优先 `exchange_size`，只有旧接口缺字段才回退 `size`，不乘杠杆、不含手续费／资金费／已实现收益。服务端 `pnl` 优先是交易所 upl，旧浮窗直接显示它而持仓卡片按 ticker 计算，导致同一行可显示 19.5 与 20；本轮已在真实模型对照中复现并统一。浮窗不再读取 REST 的 `pnl/current_price` 作为报价估值兜底，缺 ticker／有效数量时显示 `--`。
- ticker 逐事件刷新估值并立即通知 PiP，不再等待下一轮 3 秒仓位读取。持仓页与浮窗拥有独立的报价消费 session 和订阅 owner，Dashboard 对币种取并集；退出持仓页不撤掉画中画所需订阅。相同事件去重，旧 session、乱序、跨 scope 及过期事件拒绝；Store 转发子模型发布，嵌套共享状态能实际驱动 SwiftUI 更新。
- 金额继续使用 Decimal 和 [统一数字显示](ios-web-parity.md#统一数字显示2026-11-02)，持仓页／画中画的浮盈复用最多 2 位格式。读取失败保留同账户最后仓位事实，显示失败状态，不把失败当成平仓或刷新成功；成功空列表才清空持仓。切换账户／模式／绑定代际、解绑或离开登录态会 reset、取消共享 Task 并清空报价，旧响应不能回写。UserDefaults 保留旧开关和历史拖动位置键，当前不再读取拖动位置，不存仓位、报价、盈亏或凭证。
- PiP 每个 ticker 变化立即提交当前画面，另用 common run-loop mode 的 1 Hz timer 处理分页、过期和待就绪的显式启动，界面滚动不会暂停该 timer。显示图层暂不可接收时只保留最新待发送画面，由 `requestMediaDataWhenReady` 就绪后立即送出，避免直接丢帧或排队播放旧盈亏。此逻辑不增加视频帧率承诺；系统仍可挂起进程。
- 画中画按**每一行币种**的 `quoteTime` 与仓位读取成功时间中较早者判断 12 秒过期；其他币种的新 tick 或新 REST 响应不能给旧行情续期。过期／暂停显示 `--` 和“更新延迟／已暂停”，更新时间来自真实估值时间。画中画关闭／暂停后停止后台轮询，系统返回 App 会关闭本轮外部浮窗；系统挂起期间网络和渲染均可能暂停，持续后台效果需 iPhone 验收。

## ActivityKit live 持仓卡片（2026-11-03，源码实现）

持仓页右上角在浮窗按钮左侧新增独立的 `live` 入口，使用心电波形图标与 9 pt 文字，点击区为 44 × 44 pt。2026-11-07 起，开启或注册期间保留图标和文字，以模式品牌色由暗至亮循环呼吸，不再替换为转圈；减少动态效果时使用稳定亮色，无障碍状态为“正在启动”。开启后使用稳定品牌色，再次点击立即结束。它与画中画的开关独立，不提供交易操作。首次开启读取当前模式的 `/v1/position/list` 快照，初始内容和服务端后续更新均使用 REST `pnl`（交易所 upl）投影，独立于 App／PiP 的 ticker 估值模型；缺少有效绑定、系统实时活动权限或签名推送环境时提示原因。

`PositionLiveActivity.swift` 管理活动和 token；共享数据结构位于 `frontend/ios-app/Shared/PositionLiveActivityAttributes.swift`；独立 `PositionLiveWidget` 扩展绘制锁屏卡片和灵动岛。锁屏最多显示四笔的币种、方向、浮盈浮亏及更新时间；灵动岛展开显示三笔，紧凑态显示首笔币种与盈亏，额外持仓用数量提示。采用固定深色背景、黄色品牌标识及红绿盈亏，金额继续用 Decimal 精度规则，财务内容标记 `privacySensitive`，实际隐藏由系统隐私设置决定。

活动从前台发起，使用每个活动独有的 `pushToken`，与普通通知设备 token 分开。App 向鉴权 `/api/push/live-activities/register` 注册安装 ID、活动 ID、token、签名环境、模式及开始／token 更新时间；token 轮换、系统频繁更新权限变化和回到前台会重新注册。后台由独立服务器 dispatcher 读取只读持仓快照并经 APNs 更新，客户端不依赖常驻前台轮询维持 live。投递优先级、调度、迁移与开关见 [通知](signals-and-notifications.md#activitykit-live-持仓卡片2026-11-03源码实现)及 [配置](configuration.md#activitykit-live-持仓卡片)。

每份快照设置 90 秒过期时间；Widget 同时检查系统 `isStale` 与 Unix 更新时间，过期、缺值或更新失败时以 `--` 和“更新延迟”代替旧盈亏。活动最长 8 小时，之后需重新开启。恢复仅选择同服务器／用户／模式且仍有效的活动；切换账户、模式、绑定代际或退出主界面时结束旧活动，服务器另核对绑定 ID、指纹和创建时间，不能把旧身份数据更新到新活动。停止时本机立即结束并调用注销接口；服务器注销及登出通过独立结束投递收敛，不与交易写入绑定。

当前已接入客户端、Widget 与后台源码；`LIVE_ACTIVITIES_ENABLED` 默认 false。2026-11-03 22:49 已在 **47.80.22.243（首尔服务器）** 核验限定发布、独立注册表和开关 true，当前无活动注册，未发送真实 live 通知；版本与回退见 [运维](operations.md#live-后台持仓卡片限定发布2026-11-03)。源码已于前批 `8593267` 提交推送，本轮继续调整客户端；未手动上传 TestFlight。锁屏、灵动岛、Home 后系统更新、token 注册与轮换、权限关闭、过期、8 小时生命周期及切换账户仍需正式签名包真机验收；编译和隔离测试不能替代这些结果。

## 验证方式

`FloatingPositionsTests` 使用无网络 API 替身，覆盖 Decimal / 小币价、缺失值与负零、平仓后空列表、失败保留最后仓位事实／不续期、共享读取取消归属、旧账户响应、关闭后在途响应、并发请求去重和旧拖动边界纯函数；当前新增多行分页轮播、暂停 / 过期不显示旧金额及真实 IOSurface 视频帧生成测试。

`PositionLiveActivityTests` 覆盖服务器 Unix 时间解码、90 秒过期边界、缺失盈亏、Decimal 精度、四行上限与总数保留、服务器／用户／模式身份隔离，以及首帧继续使用服务端盈亏投影。2026-11-03 最终 macOS host 包直接编译实际生产类型及测试，浮窗 21 项、ticker 估值 12 项、live 4 项合计 37 项全部通过；另覆盖独立 owner／session、共享读取等待和取消、多币种过期、PiP 帧背压只保留最新值。Release 与测试目标编译通过，没有启动模拟器、ActivityKit 或真实 APNs。复现、命令和边界见 [本轮验证](development.md#持仓交互弹窗与浮窗同步回归2026-11-03)，后端既有测试范围见 [通知](signals-and-notifications.md#activitykit-live-持仓卡片2026-11-03源码实现)。
