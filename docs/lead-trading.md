# 带单模式

> 本文维护整合版沿用的业务规则；当前运行与验证边界见 [整合说明](INTEGRATION.md)。来源项目历史资料从 [来源索引](sources.md) 查询。

实现核对：2026-09-11。部署与验收状态见 [变更记录](changes.md)，本页不将模拟交易测试等同于实盘通过。

## 使用范围

“我的”下方功能菜单始终显示模式切换入口：普通合约界面为蓝色 `#58B9EF` 带单图标＋“切换带单模式”，带单界面为黄色 `#F0B90B` K 线图标＋“切换合约模式”，确认后才切换。顶部账户卡不再显示切换按钮，也不重复提供持仓浮窗入口。客户端不因 `lead_trading_enabled` 隐藏切换入口，服务端开关仍限制新绑定和开仓。带单使用蓝色主题，普通合约保留黄色；样式见 [账户与资金面板](ios-web-parity.md#账户与资金面板2026-11-02)。两者共用界面和成交、保护、结算服务，各自绑定一把 API、各自设置止损额度。带单止损额初始为 0，需要先设置。

已绑定账户的别名和头像不再打开 API 管理弹窗。账户类型标志紧跟用户名；下一行提供“解除 API 绑定”，经一次确认提交；请求期间防止重复提交和关闭确认框，失败保留绑定并显示原因。后端仍检查当前模式的交易所真实持仓、普通挂单、条件单，以及普通模式的未完成归集。成功后显示“请先绑定 API”入口，不追加绑定提醒弹窗；未绑定时点击该入口填写 API。

首期包括市价 / 限价开仓、追单、持仓、平仓、止盈止损、历史仓位和 API 管理。用户策略模板共享，订单策略快照独立；编辑模板不改写已持仓订单。带单不开放资金归集、补资邮件、转账历史、信号及研究页面。

请在币安“我的带单 → 对应组合 → API”创建专用 Key，开启合约权限并绑定服务器 IP 白名单。不要把普通合约 Key 当成组合 Key。前端只回读别名和连接状态，不返回或持久保存凭证。

## 官方接口与身份局限

- [币安带单 API 说明](https://www.binance.com/en/support/faq/detail/2bec848b904b422197ce121d0925f20b)：组合专用 API，通过 USDⓈ-M Futures 接口交易；只支持 USDT，不支持多资产保证金模式；组合资金在币安带单页面划转。关闭组合会删除其 API Key。
- [Copy Trading API](https://developers.binance.com/en/docs/catalog/advanced-trading-copy-trading/api/rest-api/future-copy-trading)：`GET /sapi/v1/copyTrading/futures/userStatus` 查询带单员状态，`GET /sapi/v1/copyTrading/futures/leadSymbol` 查询可交易币种；签名调用，成功封装为 `code="000000"`。
- `isLeadTrader=true` 证明用户具有带单员身份，不能独立证明任意 Key 都属于目标组合。当前没有可靠的组合 UID 绑定证明；专用 Key 来源仍需使用者确认，绑定成功不能被描述为已证明组合归属。

绑定校验要求明确带单员状态、`canTrade=true`、`multiAssetsMargin=false`。新开仓再检查当前 Key 的 USDT 白名单，缓存 60 秒。币种退出白名单不能阻止现有仓位平仓或保护。带单 Key 的私有请求限定 `/fapi/` 与 CopyTrading 身份 / 白名单接口，不能调用普通钱包划转或提现。

## 隔离规则

后端通过 `X-Trading-Mode: ordinary|lead` 显式选择账户，缺省 ordinary；未知值或带单未支持的路径直接拒绝，不回退到普通账户。没有服务器全局“当前模式”。

`ApiBinding` 唯一约束为 `(user, trading_mode)`，API 指纹仍全局唯一。`Order`、`LimitOrder`、`TradeOpenRequest` 持久化模式；背景任务从订单选择凭证，不读取网页当前选择。普通模式沿用原身份 / 锁键，带单增加独立命名空间；订单指纹、模式和绑定代际必须匹配。

前端切换时清理账户状态、草稿及查询缓存并重建页面。请求冻结发起时的模式与代际；快速 A → B → A 切换也丢弃旧响应和旧重试。写请求未结束时暂不允许切换，防止操作结果显示到另一账户。

## 资金、限频和后台

2026-11-05 本地新增只读 `/v1/position/margin` 白名单；只读取当前带单绑定的 FAPI 账户与配置，缓存按模式／Key／绑定代际隔离，不能回落普通账户。使用与普通全仓相同的已返回字段，不扩展带单资金操作；支持边界与新接口见 [保证金率](capital-and-transfers.md#持仓页保证金率2026-11-05本地实现)。尚未部署或用真实带单绑定验收。

止损额以该组合合约权益设置；首仓手动预检接受 1.5–5 倍止损额。低于下限或超过上限时提示去币安调整；有真实持仓时不重复首仓规范化判断，仍检查真实风险敞口上限、交易对、保证金和精度。普通模式资金规则见 [资金文档](capital-and-transfers.md)。

共用服务器和出口 IP，因此共用 Redis IP 权重预算，不能靠两个 Key 翻倍。带单额外按 Key 计 10 秒订单预算：新开仓最多使用 14 次，保护 / 平仓等关键操作可用至 18 次，为官方 20 次限制留余量；响应头校准计数。明确 `-1015` 仅暂停对应 Key 的交易写请求，不停止普通账户；未知 429 / 418 仍进入共享冷却。

同一组合的另一把 Key、币安网页和外部程序也可能消耗组合额度。当前预算按指纹而非已验证组合 UID 聚合，不能保证这些外部操作不会触发限频。Redis 不可用时的降级局限沿用 [已知事项](known-issues.md)。

带单限价同步、策略及保护任务使用独立批次和 3 个工作线程；普通池保持 10 个线程，底层仍共用进程、数据库、内存和出口。结算、手续费及清理按订单模式分组选凭证，仍有共享批次。不是两个系统的物理故障隔离，也不是无限容量承诺。

2026-09-30 手动仓扫描与强制止损已随 `85d47b0` 发布：带单使用独立 10 秒任务及带单额度快照，即使关闭新开仓入口也持续扫描有效绑定。无正数额度时显示待配置，不借用普通模式金额。面板“手动仓”和立即平仓共用普通模式语义，完整规则见 [交易安全](trading-safety.md#外部手动仓位强制保护)。线上任务已调度，但带单绑定遇到交易所鉴权拒绝并被既有健康机制置为失效；凭证、IP 或权限的具体原因尚未确定，配置阻塞见 [已知事项](known-issues.md)。

## 开关、迁移和回退

`LEAD_TRADING_ENABLED` 控制新绑定、开仓和追单。关闭后，已有带单绑定仍能返回组合、查持仓、撤单、平仓和维护保护；后台继续管理存量订单。关闭开关不会平仓、解绑或取消保护。

新增字段保留数据库默认值，以允许迁移后旧进程继续写入 ordinary 数据。先发布开关关闭的兼容基线并验收，再开放入口；存在带单数据后只能回退到识别模式的版本，不能回到一用户一绑定的旧代码。数据库不随代码回滚，禁止直接反向迁移来删除带单记录。具体发布步骤见 [运维](operations.md)。

## 验证边界

已覆盖双绑定唯一性、旧 ORM 写入新结构、跨模式访问拒绝、开仓幂等、未知提交恢复、限价部分成交、追单撤单未知、保护分批及限频隔离；底层保护重试、触价退出、平仓和结算继续复用普通交易回归。

MySQL / Redis 使用独立内网容器、测试数据和占位密钥完成并发验收，包括跨进程锁和带单预算；这些隔离测试没有访问生产数据库、缓存或交易凭证。浏览器验收使用全拦截模拟接口，真实组合 Key 绑定、币安实盘成交与跟单端结果尚待用户验证；不以真实开平仓或划转作为普通测试。

2026-09-30 发布验收确认版本、迁移、服务健康及任务调度，不代表带单交易链路实盘通过。此次带单鉴权配置阻塞及后续验证条件见 [已知事项](known-issues.md)，线上检查范围见 [变更记录](changes.md)。
