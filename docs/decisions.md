# 关键决策

本文是已采纳设计的简短决策索引，具体参数只在对应主题维护。旧方案和未实现增强见 [历史说明](archive/legacy-design.md)、[已知事项](known-issues.md)。核对日期：2026-09-11。

| 决策 | 原因与结果 | 详细依据 |
| --- | --- | --- |
| ADR-001：单体 API + 独立调度 / 通知服务 | 复用 Django 模型事务，避免 Web 多 worker 重复调度；不为单一项目引入分布式交易编排 | [架构](architecture.md) |
| ADR-002：发布与交易操作分权 | 自动发布 / SSH 可用不代表允许操作真实资金或移除保护；启动与迁移不能夹带交易副作用 | [交易安全](trading-safety.md)、[运维](operations.md) |
| ADR-003：资金规范化由用户确认 | 后台只提醒，真实空仓无挂单时才划转；持久化阶段与未知结果对账减少重复转账 | [资金](capital-and-transfers.md) |
| ADR-004：转账历史本地归档，同步独立 | 打开页面不等 Binance；每日增量 + 显式刷新，失败不覆盖旧数据。代价是非实时及当前 Key 指纹隔离 | [转账历史](capital-and-transfers.md) |
| ADR-005：外部信号先保存再翻译 | 接纳不同系统结构并保留原始对象；未知字段不拒收、不推导交易。入站企微仍是尽力转发 | [信号](signals-and-notifications.md) |
| ADR-006：通知事件与渠道投递分离 | 五类事件复用精简内容，外部服务器采用独立开关、记录和重试，便于单独移除 | [通知](signals-and-notifications.md) |
| ADR-007：历史快照 + 实时 WS + fresh 兜底 | 缓存降低首屏成本，独立行情域名规避主站 CDN WS 限制；保留直连和轮询以应对跨境失败 | [K 线](market-data.md) |
| ADR-008：私有数据不进入共享缓存 | access token 内存化、refresh HttpOnly cookie；公共行情可 CDN，账户数据不可与其共用策略 | [配置](configuration.md)、[开发](development.md) |
| ADR-009：研究策略发布不可变 | 用户样本 / 策略隔离，可复现回测；模型目录共享但选择个人化，AI 生成不执行任意代码 | [研究](research.md) |
| ADR-010：文档按主题唯一维护 | 不再叠加交接手册和任务计划；任务结束主动评估文档，历史通过 Git 及索引保留 | [维护规范](maintenance.md) |
| ADR-011：交易身份由有效绑定派生 | Web 用户不是交易所账户；Key 指纹、绑定代际和稳定命名空间统一驱动缓存、锁、幂等及客户端创建，避免重绑或跨用户污染 | [架构](architecture.md)、[交易安全](trading-safety.md) |
| ADR-012：交易所请求跨进程预算 | Redis 协调 IP 权重、优先级和冷却，响应头校准实际消耗；缓存故障时保护动作降级放行，历史等低优先级请求不能挤占交易保护预算 | [架构](architecture.md)、[配置](configuration.md) |
| ADR-013：禁止生命周期锁与活动锁反向嵌套 | 绑定、解绑和通用写操作使用生命周期锁在外的顺序；专用开仓 / 归集路径只持有活动锁并复核绑定身份，避免旧 Key 写入和锁顺序反转。代价是绑定变更需等待当前账户写操作结束 | [架构](architecture.md)、[交易安全](trading-safety.md) |
| ADR-014：交易模式在适配器边界分流 | 普通与带单共享成交和保护引擎，双绑定、显式模式及独立身份隔离账户；关键后台分批，IP 预算仍共享。先建立模式兼容基线再开放，不复制第二套交易系统 | [带单模式](lead-trading.md)、[交易安全](trading-safety.md)、[已知事项](known-issues.md) |

以后改变这些决策时记录状态、原因、兼容 / 迁移影响和验证结果，更新对应主文档；不要只新增一份互相矛盾的计划而保留旧规则为“现行”。
