原服务器为 `https://binance.oovso.com:8443`，首尔服务器为 `https://47.80.22.243`。本轮两台各 46 次正式测试（5 次新建会话探测、36 次鉴权 HTTP 请求、5 次 WSS 测试）均成功；登录、预热和退出不计入表格。完整原始耗时和失败字段见 [JSON](SERVER_NETWORK_COMPARISON_2026-10-31.json)。

当前网络下，首尔服务器的行情与 K 线请求中位耗时约为旧服务器的 2.7–3.1 倍；旧服务器本轮 K 线出现约 733 ms 的慢样本，首尔最大约 300 ms。当前样本量只能说明这一时段的单客户端表现，不能据此推断长期稳定性或并发容量。

## 测试方法与限制

- 两台交替请求，每个 HTTP 接口先各预热一次，再各取 12 次；使用独立无本地缓存的 ephemeral URLSession，鉴权请求复用连接。系统 HTTP/HTTPS/SOCKS 代理显示为关闭；测试路径仍取决于本机实际网络和路由。
- 新建会话探测每次创建 URLSession，测量 HTTPS `/api/auth/me` 的完整响应，不发送凭证；HTTP 401 且 JSON code=401 代表服务可达。客户端按钮一次采集 3 次并显示中位数，可能复用同一轮内部连接，因此不应直接等同于表中每次新建会话的值。
- WSS 复用该服务器 URLSession；ready 包含连接建立和认证时间，ping 为应用层往返。首事件等待受行情发布节奏影响，不能当作网络 RTT；本次订阅真实 BTCUSDC ticker 与 1m K 线。
- P95 使用 nearest-rank；12 个样本或 5 个样本时 P95 即本轮最大值，不能当作大样本长期尾延迟。
- 此前一次准备运行因 URLSession 超时中止，未产生有效分项报告；因此“本轮均成功”不代表整个排障过程从未超时。脚本已改为即时记录进度及正常输出错误。
- 测试账号只用于登录、读取行情/用户信息、实时订阅和退出自己的会话；没有绑定交易 API 或执行真实交易。
- 结果代表这台 Mac 当时的网络。国内手机、Wi-Fi 与蜂窝网络应分别使用设置页网络按钮并实际打开 K 线复测。

## 复测命令

在仓库根目录执行，两个账号文件必须保持 Git 忽略和 600 权限：

```bash
frontend/ios-app/scripts/benchmark_servers.sh \
  ops/.env.original-test ops/.env.seoul-test \
  /tmp/trade-tool-network-comparison.json
```

文件使用 `TEST_ACCOUNT=...`、`TEST_PASSWORD=...`；服务器地址由脚本的已知服务器列表决定。输出只含服务器地址、时间、耗时与错误，不含令牌、账号或密码。

首尔服务器同期运行快照：应用约 1.011 GiB、MySQL 637 MiB、Redis 348 MiB，系统可用内存约 917 MiB，Swap 使用 0，容器未重启。此快照包含历史补线运行阶段，不代替持续负载评估。
