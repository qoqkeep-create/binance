# 原 Web 页面与原生 iOS 对照

本主题维护原 USDT Web 的原生业务页面复刻方式。SwiftUI 实现位于 `frontend/ios-app/TradeTool/Features/USDT/`；2026-11-01 按用户新要求，认证入口 `Features/Auth/LoginView.swift` 改为 USDC 原生布局和底部 sheet，名称与图标见 [品牌与认证](ios-authentication.md)。原项目来源及只读路径见 [来源索引](sources.md)，本地参考副本和截图不属于发布资源。

## 持仓刷新与固定金额设置（2026-11-14）

本次刷新规范替代下文历史的自绘 70 pt 阈值、20×20 指示器和 56 pt 动画边距方案。共用 `WebRefreshScrollView` 使用 SwiftUI `.refreshable`，由系统管理拖动进度、读取期间占位和完成回弹；以原生 pan 结束事件保证松手后才开始网络读取，因为部分系统会提前调用原生刷新闭包。不再通过 offset KVO 每帧发布 SwiftUI 状态或同时播放内容边距动画。原生控件补无障碍标识、重复动作合并及隐藏页停用，不替换滚动 delegate、手势或 offset。

HEAD 旧版的实际模拟器手势中，拖动时能看到 spinner，读取也只在松手后开始；普通委托连续拖动加每 350 ms 等价账户发布本轮未复现逆向跳动。因此不能把用户手机的缺失提示／闪烁描述为所有环境必现，也不能仅凭旧 offset 观察和边距动画推断可见跳动。初轮“先回位再下移”的统计混入启动读取，已撤回；最终轨迹只从本次手势 arm 后开始计数。真实手机仍需配套新包验收。

最终相同手势对比中，旧版两页几何均通过，确认的旧版问题是委托刷新多读账户资料／余额；新版 9 个实际 UI 用例通过，包含两页持手可见提示、松手才读、加载期间保持区和完成后原锚点归位，以及浅深色成功弹窗居中。完整范围见 [开发](development.md#固定资金规则刷新及开仓反馈2026-11-14)。

委托／历史下拉只读取当前列表，移除账户资料、余额及保证金的整套刷新；持仓仍并发读取持仓与风险快照。卡片按 `record_key`／`id` 保持业务身份，翻页边界重复记录保留原位置并更新内容，避免相同订单产生重复 SwiftUI ID。三页签选中 20 pt、未选中 18 pt，紧凑条间距增加至 6 pt，点击区保持选中字号的固定宽度。

止损面板直接设置 50～200 USDT 固定金额，与余额无关；后端协议、归集固定 1000 USDT 和历史配置兼容边界见 [资金](capital-and-transfers.md)。市价／Maker 共用“开仓成功”弹窗，图标、交易对及说明显式铺满内容宽度后居中。

## 统一失败反馈

业务失败和 API 错误使用全局 `AppToastCenter` 错误弹窗展示，标题、消息和“知道了”按钮保持一致；用户确认前不自动关闭。成功、普通提示和警告继续使用短时 Toast。交易与行情页面只负责报告错误，不再各自堆叠一闪而过的失败提示。

## 持仓原生分页实现与边界（2026-11-06，本地）

此前共用一个纵向列表并替换 `segment`，横滑达到阈值便立即换内容及归顶，因此表现为“秒切／刷新”；不代表每次都重新下载数据。本轮按用户确认采用原生分页，代码位于 [PositionNativePager.swift](../frontend/ios-app/TradeTool/Features/USDT/PositionNativePager.swift)，并移除旧的窗口级即时切页 pan。UIKit 的 [分页](https://developer.apple.com/documentation/uikit/uiscrollview/ispagingenabled)和[松手目标位置委托](https://developer.apple.com/documentation/uikit/uiscrollviewdelegate/scrollviewwillenddragging(_:withvelocity:targetcontentoffset:))负责滚动及落点；不使用私有视图查找、定时器或自写逐帧位移动画。顶部是同一 UIScrollView 内固定的独立宿主；三页各为保留的 SwiftUI 宿主，环境由当前 representable 显式传递，弹窗与交易确认仍在根页面。

真实按下点通过立即失败的被动触摸观察器记录：系统 pan 开始识别时会扣除部分初始位移，不能直接把其剩余 translation 当作用户滑动距离。观察器不驱动滚动、不取消控件触摸，也不与原生滚动争夺识别。拖动过程中数据更新复用相同宿主且不重置偏移；旋转重排后对齐当前页，弹窗／隐藏／后台取消未完成拖动并对齐已选页。无障碍仅暴露当前页，避免相邻页同名按钮和隐藏操作混入当前页面。

保留三个视图会增加视图与布局开销，列表继续惰性构建，网络缓存和活动订阅按现有规则运行；不宣称内存数值、帧率或接口耗时的定量改善。首次尚无缓存的页面仍需要加载。此轮只改客户端，需要新包；验证结果见 [开发](development.md#持仓原生分页与系统组件盘点2026-11-06本地)。

## 原生实现与系统组件盘点（2026-11-06，源码核对）

当前 iOS 主业务页面均为 SwiftUI／UIKit／Metal，源码未发现 WebKit／WKWebView 或 HTML／JavaScript 业务页面。行情与自选、Metal K 线及指标、持仓／限价／历史、信号、账户／API、止损、策略、资金／日志、登录／注册／找回密码和协议页面都已是原生。`WebTabs`、`WebModal`、`webSheet` 等名称沿用原网页视觉规范，不能理解为嵌入网页；“使用自定义原生控件”和“不是原生页面”须区分。

用户随后确认实施前三类改造；下表为当前源码实现，本批完整交付范围见 [变更记录](changes.md#2026-11-06系统组件与透明小圆角分段源码交付)：

| 位置 | 当前实现 | 是否值得改用系统现成控件 |
| --- | --- | --- |
| 持仓／限价／历史分页 | 本轮改为原生 UIScrollView 分页，保留三页状态 | 已实施；动态手感仍需新包实机确认 |
| 登录表单、交易对选择、周期／杠杆、资金、策略管理等大面板 | `nativeTradingSheet` 系统 sheet；旧 `webSheet`／`largeTradingSheet` 入口委托同一容器 | 已本地改造；保留 96%／80%／60% detent、背景、24 pt 圆角、提交锁及嵌套导航，详见下节 |

## 大面板、开关与资金分段迁移（2026-11-06，本地）

## 图表与账户反馈（2026-11-03）

K 线收藏星标使用明黄色 `BinanceTheme.accent`，币种下拉箭头增至 10 pt。未选择有效止损时，开仓提示为绿底白字“在 K 线图上选择止损价开仓”。开多按钮、选止损提示和 auto 开关经 `ChartTradingPalette` 读取与 MACD 柱体完全相同的 `ChartColor.positive.resolved(for:)`；开空读取相同主题下的 `ChartColor.negative`，不再另用 `BinanceTheme.positive`。此前按钮自定义样式在禁用时对整体应用 0.5 opacity，导致红绿与背景混合、看起来浅灰；现移除该衰减，按下时仍保留 0.8 反馈，交易禁用条件与选价校验不变。止盈入口现为文字＋下划线＋右箭头，移除黄色底：未保存自动策略默认“手动止盈”；已选择的手动或自动策略使用正常正文色，自动策略名单行尾部省略；失效或缺失的已选策略显示红色“选择止盈方式”，提交按钮显示“请选择止盈方式”并保留完整底色。开仓结果、资金预检与读取失败统一走公共 `AppToastCenter`，下方不再堆叠小字说明或操作结果。

“我的”资料刷新原先只识别原生 `CancellationError`，网络层包装后的 `APIError.cancelled` 会被当成业务错误展示“请求已取消”。现按 `APIError.map(...).shouldPresent` 过滤，并在状态写入前同时核对任务取消与账户范围；正常切页取消不展示提示，成功刷新清除旧提示，真实请求错误继续反馈。此结论由取消回归替身复现并验证，不能据此推断所有网络错误均可隐藏。

杠杆入口默认读取既有 `GET /v1/trade/symbol/info` 的 `max_leverage`，显示“杠杆 × 最大倍数”；有手动确认值时优先显示该值。读取期间显示“杠杆 · 读取中”，不伪造倍数；内部标题为“杠杆”（18 pt）、档位倍数 20 pt、可开金额标签 11 pt／数值 16 pt。默认展示继续沿用后端自动最大杠杆路径，不会因只读加载写入交易所或给订单加显式杠杆。按有效 `max_open_amount` 排序且最多展示三档，缺金额时提示重新读取，不用标准名义额度代替实际可开金额。确认保存当前币种及账户范围的选择。杠杆、资金面板显式传入 `WebTheme.page`；止损面板改为 `WebTheme.surface` 且隐藏顶部灰色控制柄，浅色标题与表单保持白底。交易对等面板保留自己的背景。

“我的”模式入口位于下方功能列表的最后一项，紧接“设置”下方，普通模式显示“切换带单模式”和当前合约黄色带单图标，带单模式显示“切换合约模式”和当前带单蓝色 K 线图标；顶部只保留头像／账户信息和归集入口。余额在进入页面或用户点击刷新／下拉刷新时通过 `fresh=1` 重新读取；停留时不设余额轮询，账户事件仅刷新绑定、资料、策略和持仓修订，不再隐式重读余额。刷新按钮保留至少 60×44 pt 点击区，读取时显示进度。历史仓位隐藏“资金费来自持仓时间窗口”说明段，其他结算依据继续显示。资金面板规则见 [资金](capital-and-transfers.md#原生划转与转账2026-11-02)，图表渲染及数据修复见 [行情](market-data.md#拖动一致性当前价与尾线修复2026-11-03)。

## 统一数字显示（2026-11-02）

## 返回手势与弹窗（本地改动）

2026-11-01 按用户确认统一层级返回：每个 UINavigationController 共用一个公开 UIKit 交互转场与 Pan recognizer，左侧 50 pt 范围起手，按水平方向、距离和速度判断完成或取消。SwiftUI 原导航代理继续接收回调；根页面不触发返回。K 线图同步预留左侧 50 pt，时间轴横拖从该范围外起手，避免与返回争夺。横向表格在最左边界让出返回手势，已横向滚动时先恢复表格位置；输入框和滑杆避让。

覆盖列表设置、K 线、图表指标与下单设置，以及转账历史、设置、日志、策略列表与编辑、交易命令。二级页面通用标题栏的返回图标统一使用左向开口箭头（Lucide `chevron-left`），点击区 44 × 44 pt；行情的原生返回按钮同样使用 `chevron.left`。实际模拟器覆盖范围写入变更记录，不能以公共修饰器存在替代逐页真机验收。

公共 `webModal` 的 Bool／item 入口均默认原位淡入淡出（打开 0.16 秒、关闭 0.14 秒），不再让小弹窗因首次零高度或暂态内容被误判为上滑。弹窗通过上述 UIKit 屏幕级透明宿主呈现，不使用源组件局部 overlay 或系统 `fullScreenCover`；首次有效布局前卡片及蒙层保持隐藏、无位移。卡片和蒙层使用同一动画进度，蒙层始终原位渐变；嵌套确认按底层已有遮罩补足透明度，避免重复叠黑。保本损、止盈、立即平仓、策略日志和自动策略选择均保持 fade，减少动态效果继续沿用该 fade。共用 `webSheet`／`largeTradingSheet` 及策略管理仍由系统 sheet 接管动画及动态效果偏好；键盘或内容高度变化不切换展示器。

大面板下拉关闭与回弹由系统负责，小弹窗下拉时继续原位淡出；未达到关闭条件则恢复。提交锁适用于资金、认证和持仓策略面板；注册／密码表单及策略管理使用系统 sheet，保留拖动条与 24 pt 圆角。图表与下单区统一在标准导航页面显示；导航子页右滑返回。

止损设置使用 80% detent 的系统 sheet，24 pt 圆角，取消顶部灰色控制柄及独立底色区域，浅色标题与内容均为白色 surface，深色使用对应 surface。标题固定、表单滚动，底部“确定”放在 `safeAreaInset` 内保持位置稳定。原生 `Slider`、数据返回一次性无动画更新和局部倒计时继续保留。提交中禁止重复操作与关闭，二次确认使用原位淡入淡出。金额显示通过 `WebStopLossAmount.text` 最多保留 3 位小数、四舍五入并去尾零（`10.5000 → 10.5`、`123.4565 → 123.457`），百分比直接显示整数；原 Decimal 计算、向上取整步长及提交接口沿用既有实现。

大面板根页关闭通过本层系统 dismiss／展示绑定，嵌套导航子页继续使用导航返回，避免退出整个面板。认证下拉测试从实际面板头部起手，不依赖系统 sheet 的固定屏幕坐标。

暗色 Tab Bar 背景为 `#212731`，顶部资产卡使用上述 USDT 品牌色渐变，其余卡片与边线见上表。业务尺寸沿用既有复刻实现。

## 业务与测试边界

页面继续通过 `USDTStore` 使用既有 Python API、账户模式和持久化命令。主按钮按订单类型及止损方向显示市价／限价开多或开空，点击后直接进入资金预检与订单确认；选择策略进入“我的策略”，确认成功后返回 K 线。资金整理预检判断 `normalization_required` 和有效计划，不能因归集金额为零而禁用仅补入资金的计划。止损预览使用 Decimal，原值小于 20 按 1、小于 100 按 5、其余按 10 向上取整，服务端仍为最终依据。

持仓弹窗携带所选持仓和动作，避免首次呈现旧数据。批量平仓逐笔复用已有 `position-close` 命令，在发送前保存当前账户范围的目标与幂等键；未知或非终态停止后续处理，并沿用原键核对。切换账户范围后停止该批处理。普通测试只检查入口和确认界面，不执行真实平仓；会话、绑定代际与服务端未知结果恢复仍遵守 [交易安全](trading-safety.md)。原有资金、幂等和保护规则继续保留；2026-11-03 开仓初筛退役范围见 [交易安全](trading-safety.md#图表与标准开仓共用流程2026-11-02)。

重置密码支持解析已有 `reset_uid` / `reset_token` 参数；邮件 HTTPS 链接自动唤起 App 的 Universal Links 关联尚未专门配置和验收。SMTP 和通知真实发送仍遵守 [已知事项](known-issues.md)。

## 本地校对

`WebParityUITests` 位于 `TradeToolChartCalibrationUITests/ChartCalibrationUITests.swift`，使用 DEBUG 专属启动参数 `--web-parity-fixture <page>`。该 API 无网络 transport；只有资金预检允许返回本地静态 POST 预览，其他写操作全部拒绝。采用独立 fixture 用户和会话空间，不读取生产账号或交易凭证，Release 不包含该入口。

提示条回归参数 `--fixture-toast` 在本地替身展示一条持续 30 秒的两行提示；正常运行继续使用原有 1.5 秒自动消失。刷新回归专用参数 `--fixture-refresh-lists` 使持仓、限价和历史各自首次读取为空、下拉后返回静态记录，用于验证三个空列表实际触发重新请求；不连接网络。

`--fixture-history-supplement-slow` 为已绑定历史页返回本地待结算记录，并将后续核对延迟 6 秒；`testBoundHistoryShowsRecordsWhileExchangeSupplementIsSlow` 检查核对期间能看到记录和状态，最终进度消失。`testAllUnboundPositionTabsOnlyShowBindingPrompt` 覆盖三个页签的居中绑定入口及表单打开。

附加状态参数为 `--fixture-dark`、`--fixture-lead`、`--fixture-empty`、`--fixture-unbound`、`--fixture-multiple`、`--fixture-capital-refill`。页面包括 `market`、`launch`、`trade`、`positions`、`signals`、`profile`、`strategies`、`strategy-editor`、`operations`、`transfers`、`settings`、`legal`、`privacy`、`binding`、`stop-loss`、`collect`、`capital`、`reminder`、`login`。行情延迟替身默认 86 ms（绿），`--fixture-latency-fair` 为 280 ms（黄），`--fixture-latency-slow` 为 780 ms（红）；`--fixture-latency-overflow` 模拟 1520 ms 并显示 999，`--fixture-latency-unavailable` / `--fixture-latency-measuring` 分别模拟不可用（红色 `-- ms`）与首次测量（`-- ms` 加小型圆形进度）。点击或下拉重测保留读数并显示进度，800 ms 后恢复固定 86 ms，`--fixture-latency-refresh-slow` 将此过程延长至 6 秒，覆盖 UI 自动化等待下拉回弹的时间，只用于校对中间状态。这些 UI 替身不建立网络连接；实际探测口径见 [行情](market-data.md)。
